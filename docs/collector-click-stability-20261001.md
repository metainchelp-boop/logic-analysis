# 클릭 위치 안정화 — 1.28.4-rc1

## 승인된 설계와 범위

기준: `892f2c1`, 확장 `1.28.3-rc1`. 사용자는 2026-10-01 진단·수정안 설명 후 “그럼 개선 작업 진행해”로 구현을 승인했다.

좌표가 이동해 빈 곳을 클릭하는 재현을 해결한다. 고정 대기만 늘리는 안은 이동 후 배치 변경을 해결하지 못했고, 위치 안정 및 마우스 이동 후 재검사를 적용한 임시 후보는 해당 재현을 해소했다. 검증을 완화하거나 반복 클릭하는 안은 채택하지 않는다.

- 현재 대상 판별 규칙은 유지한다. `pagerLocate`의 내부 guard 옵션으로 같은 DOM 요소의 연결·위치·가림을 재검사한다.
- 페이지의 연속 위치 검사에는 독립 타이머를 두고, worker에도 제한 시간을 둔다. 불안정·요소 교체·확인 실패 시 합성 클릭으로 우회하지 않는다.
- debugger 미지원 또는 attach 전 실패만 기존 합성 입력 경로를 허용한다. 누르기를 시도했다면 전달이 불확실해도 두 번째 클릭을 하지 않는다.
- 한 번의 클릭에 대해 실제 수신 여부와 요소 교체·이벤트 취소를 값 없는 제한된 진단으로 관측한다. 관측 부재를 입력 미전달의 확정 증거로 해석하지 않는다.
- 입력 전달은 이동·순위 저장 성공이 아니다. 기존 응답 출처·페이지 정체성·최신성 검증과 부분 수집 처리는 그대로 둔다.
- 휴식·차단 대기·서버 작업 분배·미전송함·권한은 변경하지 않는다. 서버 배포·원격 노트북 조작·실사이트 수집 요청은 하지 않는다.

## 구현·검증 순서

1. 실제 스크롤을 포함한 Chrome 재현 시험을 추가해 원본의 smooth 실패를 확인한다.
2. 위치 안정 및 이동 후 재확인으로 해당 시험을 통과시킨다.
3. 가림·계속 이동·요소 교체·이벤트 관측·타임아웃·중복 입력 방지 시험을 차례로 추가한다.
4. 기존 확장·수집 관측·서버 회귀를 실행하고 독립 리뷰로 안전 조건을 확인한다.
5. 버전 두 필드만 올리고 8개 런타임 파일의 교체 ZIP을 만든다. 압축 무결성·소스 동일성을 검사한다.

## 합격 범위

로컬 회귀 합격과 Windows 현장 합격을 구분한다. 현장에서는 새 버전의 새 관측으로 실제 2페이지 응답과 서버 상품 기록을 연결해야 한다. 서비스 제한 해제나 오전 10시 처리량은 이 패치로 보장하지 않는다.

## 새 진단 읽기

기존 자동 TAP_PROBE의 click에 아래 필드를 추가했다. 새 서버 배포나 별도 진단 요청은 필요 없다. 본문은 여전히 500자 이내 유효 JSON이며 검색어·상품·DOM 원문을 추가하지 않는다. 기존 별도 keyword/href 필드나 예전 원문 보고까지 익명화했다는 뜻은 아니다.

- guard: covered(가림), unstable(위치 안정 미확인), changed(대상 교체/연결·주소 변경), outside(화면 밖), timeout(시간 초과), error(검사 실패), no-target(대상 없음), unavailable(debugger 사용 불가), pending(전달 시도·수신 미확인), received(대상의 trusted click 관측). received도 페이지 이동·앱 처리·저장 성공을 뜻하지 않는다.
- ev: 비트 합계. 대상의 pointerdown=1, mousedown=2, pointerup=4, mouseup=8, click capture=16, click bubble=32, trusted click=64, 관측 클릭의 최종 defaultPrevented=128, 다른 요소의 입력=256. 이벤트 부재는 앞선 이벤트 처리기가 전파를 중단했을 가능성도 있으므로 입력 미전달로 단정하지 않는다.
- gone: 관측 종료 때 원래 요소가 문서에서 분리됐는지. 정상적인 화면 교체에서도 true일 수 있다.
- js: 같은 관측 구간의 페이지 오류/처리되지 않은 Promise 거절 수(최대 9). 원인이나 오류 원문은 아니다.
- ev/gone/js의 null은 관측 자료를 확보하지 못했다는 뜻이다. 이전 페이지의 값을 재사용하지 않는다. 수동 HUMAN 진단에는 과거 자동 클릭 관측을 넣지 않는다.

페이지 검사 1회는 1.5초, worker의 주입 응답 대기는 2.2초 한도로 멈춘다. 마우스 위치 조정은 최대 3회이며 누름은 최대 1회다. 관측기는 finally에서 제거하고, worker 종료 등에 대비한 10초 정리 타이머도 둔다. 브라우저가 페이지를 완전히 정지시킨 동안에는 페이지 타이머 실행 자체가 지연될 수 있지만 worker는 늦은 검사 결과로 클릭하지 않는다.

## 신규 안전 시험과 교체 파일

- 신규 실제 Chrome 입력 회귀: 12/12 통과(최종 46.594초). 실제 운영 스크롤·sleep·debugger 래퍼를 실행하고 Chrome API 경계만 CDP로 연결했다. smooth, 마우스 이동 후 위치 변경, 계속 움직임, 가림, 누르는 중 요소 교체, 프레임 미발생, 주입 거절·응답 유실, press/release 전달 후 오류, attach 실패를 확인했다. 모든 시나리오에서 document/window 이벤트 리스너가 시작 전 상태로 복원됐다.
- 원본 smooth 시험은 1페이지 잔류로 실패했다. 수정 후 단일 클릭으로 2페이지에 진입했다. press 전달 후 ACK 오류 시험도 release가 0회인 상태에서 실패시킨 다음 보완했다. 이제 아직 release를 시도하지 않은 경우에만 해당 입력의 release를 최대 1회 마치며, 이미 시도한 release나 press를 반복하지 않는다.
- 입력 오류 후 release 정리에도 별도 2.2초 제한이 있다. 시간 초과가 전송 취소는 아니므로 늦은 입력 관측이 빠질 수 있다. 이때도 pending과 기존 페이지 검증을 유지한다.
- 이 시험은 Windows 확장 설치, 실제 debugger 안내 띠, 실제 숨김 탭, 실제 네이버 동작을 검증한 것이 아니다. 프레임 미발생은 브라우저 타이밍 경계를 통제한 시험이다.
- manifest는 버전 두 필드만 바뀌었다. 권한·호스트·주입 시점은 기준판과 같다. 런타임 JS 문법과 diff 검사 통과.
