## 제품 변경

### 연결 사유

- 기존 확정 허용 조건을 `block_reason`과 불리언 래퍼로 공유한다. 확정 정책은 그대로다.
- 공개 응답 `confirm_block_reason`으로 최초 거절 사유를 추가한다.
- 화면은 계약 종료일·원천 갱신·담당 권한·충돌 등에 해당하는 고정 한국어 사유와 다음 행동을 보여준다. 알 수 없는 코드나 원문 오류를 그대로 출력하지 않는다.

### 수집기 표시

- 모든 탭의 공통 상단에 원형 상태와 설명을 표시한다. 색만으로 정보를 전달하지 않는다.
- 초록: 원천 동기화 중, 수집 중, 정상 호출 간격 대기, 이번 회차 처리 완료. 회차 완료는 전체 계정 완료를 뜻하지 않는다.
- 빨강: 비활성, 시작 준비, 중지, 호출 제한 일시정지, 원천·인증 문제, 실행 오류, 진행 신호 만료, 상태 확인 불가.
- 실제 실행 스레드의 작업 진입·종료, 기존 HTTP 전송, 기존 대기만 관찰한다. 별도 심박 타이머나 화면 조회로 진행 신호를 연장하지 않는다.
- 단조시계로 신선도를 만료시키며 실제 HTTP timeout, 짧은 내부 처리, 기존 예약 대기 범위만 인정한다. 원천 실패나 실행 오류는 빈 회차만으로 정상 해제하지 않는다.
- `GET /health?runtime=1`은 기존 로그인·조직·담당 권한을 거친 뒤 고정 필드의 메모리 상태만 반환한다. 네이버·전산 외부 요청, 수집 예약, 상태 변경은 하지 않는다.
- 화면은 기본 15초 간격, 짧은 진행 신호는 만료 전에 재확인한다. 요청 중복 방지·10초 요청 제한·탭 비노출 시 조회 중지·로그아웃 정리·클라이언트 만료 처리를 포함한다.
- 기존 내부 건강 확인, 수집 호출 예산, 429 대기, 작업 재시도 정책은 바꾸지 않는다.

## 검증과 남은 경계

- 합성 공개 API, 허용 여부 비교, 실행기/전송 상태, 무응답 만료, 권한, 화면 회귀로 검사한다.
- 로컬 파일 Store 시험 일부는 변경 이전에도 재현된 macOS `open_writer/OperationalError` 때문에 실행 단계에 도달하지 못했다. 이를 통과나 운영 성공으로 집계하지 않는다. Linux CI 결과를 별도로 남긴다.
- 기존 수동 조회는 별도 작업을 만드는 방식이며, 과거 작업의 실제 오류 예산을 승계하지 않는다. 이를 이용해 제한 작업 전체를 무조건 다시 열지 않는다.
- 계약 종료 후 14일 보호로 막힌 업체는 전산 계약의 사실 확인·정정 또는 별도 정책 결정이 먼저다. 계정 이름이 다르다는 이유만으로 차단된 것으로 안내하지 않는다.

- 관련 통합 검사 33개 및 VM 내부 사례 90개가 통과했다. 전체 Linux CI와 실제 브라우저 재검증은 별도 결과로 확인해야 하며, 부분 통과를 운영 완료로 간주하지 않는다.
