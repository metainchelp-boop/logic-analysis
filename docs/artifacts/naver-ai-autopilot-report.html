네이버 광고 AI 자동운영 — 1차 쇼핑검색 설계 보고서

대표님 확정 사항(쇼핑 → 파워링크 → 플레이스 · 공식 대행사 매니저 계정 · 광고주 약 800곳 · 승인 없이 자동은 「A/B 테스트」와 「상한 있는 입찰가 조정」 두 가지뿐)을 그대로 두고 설계했습니다. 조사 5건을 한 뒤, 세 방향(네이버 API 정확성 · 돈·안전 · 800곳 규모)에서 일부러 흠을 찾는 검토를 거쳐 고쳤습니다.

결론: 만들 수 있습니다. 다만 코드보다 먼저 실계정으로 확인할 것이 있습니다.

숫자(입찰가)는 시험된 계산 규칙이 정하고, AI는 계획·원인 진단·설명·분류만 합니다. 네이버에 쓰는 문은 하나만 두고, 그 문은 쇼핑 입찰가 두 칸만 승인 없이 엽니다.

그런데 「상품 하나의 입찰가를 바꾸는 방법」과 「매니저 계정으로 광고주 800곳에 쓸 수 있는지」가 네이버 공식 문서에 적혀 있지 않습니다. 그래서 실계정 1곳에서 먼저 확인(0단계)하고 나서 만드는 순서로 잡았습니다.

1. 무엇을 만드나

③ 광고센터 안에 「🤖 자동운영」 메뉴가 새로 생깁니다. 기존 화면은 그대로 둡니다.

화면하는 일
자동운영 관제엔진이 돌고 있는지, 오늘 무엇을 바꿨는지, 사람이 처리할 일이 무엇인지 한 화면. 급하면 「전체 비상 정지」

승인 대기함자동이 아닌 일(예산 변경·켜고 끄기·상한 올리기 등)을 광고주·날짜 묶음으로 한 번에 승인

2. 돈이 새지 않게 막는 장치

검토에서 가장 크게 나온 위험과, 이렇게 막았다는 것만 적습니다.

위험막는 법
가장 큼 매니저 키 하나로 800곳 어디든 쓸 수 있어서, 짝짓기가 틀리면 남의 광고계정에 쓰게 됨쓰기마다 「방금 읽은 계정 번호 = 작업 계정」 확인 · 짝짓기는 사람이 확정한 것만 · 동의서에 적힌 계정만 자동
상한이 상품 단위뿐이라 계정 전체 지출이 불어날 수 있음계정 하루 지출 상한을 필수로. 넘을 기세면 그 계정 올리기 전부 멈춤(내리기만 허용) + 알림
자정마다 누적 한도가 새로 시작되면 날마다 +30%씩 쌓임누적은 최근 24시간 · 7일 · 30일로 굴려 셈. 7일에 +50% 넘으면 승인
A/B 를 클릭 수로 판정하면 늘 「비싼 쪽」이 이겨 입찰이 한 방향으로만 오름판정은 목표 효율(추가 클릭 1개 비용·CPA·ROAS)로만 · 실험 폭은 1회 한도 이하 · 같은 상품 재실험 14일 쉼
엔진을 멈춰도 올려 둔 입찰가로 광고가 계속 돔비상 정지에 「멈추고 원래 값으로」 · 계약 정지·동의 철회 때 엔진이 올린 몫만 자동으로 내림
환불 요청한 광고주를 하루 넘게 계속 운전전산 계약 단계를 6시간마다 확인 · 조회가 하나라도 실패하면 그 회차 쓰기 멈춤 · 「재계약 진행중」도 목록에 넣음
저장 실패로 한도 계산이 빠지는 틈「이렇게 바꾸겠다」를 먼저 저장한 뒤 네이버에 씀. 먼저 저장이 안 되면 쓰지 않음
기존 쇼핑 자동입찰(9/10 중지)이 푸시 한 번으로 다시 켜질 수 있음코드 흡수 전에 그 재배포 길부터 막음(대표 결정 D4)

3. 「A/B 테스트」는 이렇게 정의했습니다

쇼핑검색에서 실제로 할 수 있고 승인 없이 돌려도 되는 것은 입찰가 실험뿐입니다.

  • 날짜 교차: 같은 상품을 날짜별로 입찰가 A(지금 값)와 B(조금 높거나 낮음)로 번갈아 둡니다. 요일 영향을 빼려고 14일 전에는 판정하지 않습니다.
  • 상품 나누기: 비슷한 상품을 무작위로 두 편으로 나눠 입찰가를 다르게 둡니다(상품 입찰가 쓰기가 0단계에서 확인되면).
  • 판정 기준은 95% 이상 확신. 모자라면 「판정 불가 · 지금 값 유지」가 기본입니다.
  • 새 그룹·소재·광고문 실험은 A/B 가 아니라 승인 대상으로 둡니다.

솔직한 한계: 하루 20클릭 정도의 작은 광고주는 14일을 돌려도 큰 차이(약 1.4배)만 가려집니다. 작은 광고주는 A/B 보다 상한 안 입찰 조정이 주로 돕니다.

4. 만드는 순서

0
관찰 + 실계정 확인 — 실계정 1곳에서 읽기 전부 + 쓰기 2건만 확인. 시범 20곳 자료를 14일 모으고, 엔진은 「이렇게 했을 것」만 기록(실제 쓰기 없음).
1
제안 — 엔진 결정을 승인 대기함에 올리고 담당자가 승인한 것만 적용. 4주 운영, 알림·되돌리기·AI 설명 가동.
2
자동(A/B·입찰만) — 5곳 → 20곳 → 100곳 → 800곳. 단계마다 대표님 확인. 100곳 넘기 전 DB·서버 다시 결정.
3
파워링크 — 키워드 입찰(200개씩 한 번에 가능). ⚠️ 새 그룹을 만들 때 네이버 AI 입찰(ADVoost)이 기본으로 켜지므로 반드시 끄고 만듦.
4
플레이스 — 네이버 AI 입찰을 켠 그룹은 입찰가를 못 바꿔 읽기 전용. 따로 설계.

5. 0단계에서 실계정으로 확인할 것

★ 쓰기는 두 건뿐이고 둘 다 「10원 올림 → 바뀐 것 확인 → 원래 값으로」입니다. 나머지는 전부 읽기입니다.

#확인할 것
1매니저 키로 광고계정 1곳의 캠페인·그룹·상품 읽기
★2그룹 기본 입찰가 1건 +10원 → 확인 → 원래 값
★3상품 하나 입찰가 1건 +10원 → 확인 → 원래 값 (문서에 없는 방식이라 여기서 가부가 갈림)
4~5상품 입찰가를 읽을 수 있는지 · 바뀐 값이 보고서에 언제 반영되는지 · 「읽기만」 권한 계정 구분
6네이버 자체 쇼핑 자동입찰이 켜진 그룹 · 하루 예산 · 공유 예산 현황
7~10시간대별 통계 · 예상 입찰가 · 비즈머니 잔액 · 보고서를 매니저 키로 받을 수 있는지 · 전환 추적 판별
11~12800곳 중 쓰기 권한·쇼핑 사용·구매 전환 수집 비율 · 우리 광고주끼리 같은 검색어에서 겹치는 비율(시범 20곳)
13(먼저) 옛 쇼핑 자동입찰 재배포 길 차단 · 남은 저장소(볼륨) 처리 · 맥미니 에이전트 종료

★3이 실패하면: 1차는 그룹 입찰가만으로 운영하고, 상품 단위 조정·상품 나누기 A/B 는 빠집니다. 매니저 키 쓰기가 안 되면 광고주별 키를 받아야 해서 확대가 크게 느려집니다.

D7광고주 동의서자동 범위 · 입찰 상한 · 계정 하루 지출 상한 · 실험 · 비상 정지 권한 · 적용 계정 목록 · 문구는 법무 확인

D12네이버 자체 자동입찰 켜진 그룹건드리지 않음(읽기·보고만)

7. AI 모델은 이렇게 바꿔 끼웁니다

  • 역할 네 개(계획 · 원인 진단 · 설명 · 분류)마다 모델을 설정 한 칸으로 둡니다. 지금 권고는 계획·진단 Claude Opus 5, 설명 Claude Sonnet 5, 분류 Claude Haiku 4.5.
  • 새 모델이 나오면 지난 기록으로 시험 → 실행 없이 나란히 돌려 비교 → 광고주 10%에만 → 전체 순서로 바꿉니다. 되돌리기도 설정 한 칸입니다.
  • 입찰 숫자는 규칙이 정하므로 모델을 바꿔도 돈이 움직이는 방식은 안 바뀝니다.
  • AI 비용(추정): 800곳 전원이면 월 약 $940~$1,080, 시범 20곳이면 월 약 $24~$50. 시범에서 실제로 재서 다시 계산합니다.

8. 솔직한 한계

  • 상품 입찰가 쓰기 방식 · 매니저 키로 800곳 쓰기 가능 여부 · 네이버 호출 한도 숫자는 공식 문서에 없습니다. 0단계에서 확인합니다.
  • 네이버 통계는 약 2시간 늦게 들어오고, 전환 매출은 며칠 뒤 고쳐지기도 합니다. 「즉시 되돌리기」도 실제로는 2~3시간 뒤입니다.
  • 네이버 자체 자동입찰이나 다른 프로그램이 같은 상품 입찰을 바꾸면 바뀐 뒤에야 알아챕니다. 알아채면 엔진이 그 상품에서 손을 뗍니다.
  • 광고센터는 자동 시험·자동 배포가 없고 서버를 다른 섹션과 나눠 씁니다. 100곳 넘기 전에 서버·DB를 다시 정해야 합니다.
  • AI의 계획·진단 품질은 시험 문제가 쌓이는 1단계 끝까지 객관적으로 채점할 수 없어, 그 전까지는 참고용 제안으로만 씁니다.
