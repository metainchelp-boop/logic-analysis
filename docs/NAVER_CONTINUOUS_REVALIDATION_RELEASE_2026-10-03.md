# 지속 수집·실적 정정·화면 확장 통합 배포

## 승인 범위

대표의 2026-10-03 「응 배포해」 승인에 따른 단일 배포다. 전일 자료는 한국시간 00:01부터 읽고 10:00을 목표로 하되 미완료 작업은 이후에도 이어 간다. 관리 대상의 최근 3일과 일요일 최근 31일, 닫힌 보고 기간을 재확인한다. 권한 있는 직원의 최대 31일 과거 기간 재확인은 요청 때의 기간·업체·종류를 고정한다.

일별 정정은 감소와 명시적 0을 포함해 원천 개정 이력을 남긴다. 같은 업체의 영향을 받는 주간·월간 보고서는 같은 저장 거래에서 게시하고 이전 판과 차이를 보존한다. 숫자가 그대로면 새 판을 만들지 않으며 검증 시각만 갱신한다. 재확인 대기 중이거나 원천 세대를 확인할 수 없는 보고서는 새 검토 승인을 받지 않는다. 주간 월요일·월간 3일 10시는 초판 생성 목표이며 완결 보장이 아니다.

전체 여섯 탭은 화면 폭을 사용하며 좁은 화면에서 표를 항목명 있는 카드로 전환한다. 내부 표·탭·보고서 이력도 가로 넘침을 검사한다. 네이버 광고 쓰기·자동입찰·알림·외부 보고서 전송·유료 AI·전산 계약/담당 원본 변경은 포함하지 않는다. 직원 Chrome 진입 문제도 별도 범위다.

## 기존 운영과 복구

기존 실행 소스는 `657d98d12b7d84c1e34b6fc61c5fad830e5c0377`, schema10이다. 신규 schema11은 기존 SQL과 행을 보존하고 8개 열·2개 표·1개 색인만 추가한다. 코드/압축/Store 전체 지문과 이관 구문을 고정한다. 쓰기 종료와 일관 사본을 검증한 후 전용 엔진·릴레이만 교체하며, 실패하면 실패 DB를 보존하고 schema10 사본과 구버전 코드를 함께 복원한다. 기존 앱·nginx·bootstrap·키 설정 변경은 없다.

## 배포 전 검증 이력

- 후보 `42a062d`의 Linux CI `37028974239`는 실패하여 운영에 반영하지 않았다. 구조 수동 조회의 세대 불일치, 저장 연결의 단일 모듈 규칙 위반, 실제 브라우저 검수 선택자 중복, 구형 대기 상태·문구 시험을 발견했다. 저장 검사를 완화하지 않고 보고서 SQL을 Store 안으로 모았다.
- 독립 검토에서 접수 후 worker 시작 전 보고서 승인 가능 구간과 이전 세대의 늦은 응답이 최신 대조 완료로 보이는 구간을 발견해 회귀시험과 함께 차단했다. 이슈 상태만 바뀐 보고서도 재계산하게 보완했다.
- 로컬 순수/메모리 SQL/웹 시험은 실제 파일 잠금·운영 사용 검증과 구분한다. 최종 Linux CI, 봉인, 준비, 적용 및 적용 후 독립 상태·화면 결과는 아래에 실제 확인 후 기록한다.
