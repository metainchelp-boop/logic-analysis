# 첫 진입 주소·페이지 버튼 오인 보완 — 1.28.3-rc1

## 기준과 승인 범위

- 기준: `3cbeaad`, 확장 `1.28.2-rc1`.
- 사용자 승인: 교체 후에도 남은 첫 페이지 오류와 2페이지 실패를 보완합니다.
- 구현 순서: 재현 → 최소 수정 → 회귀/격리 Chrome 시험 → 교체 ZIP 검증.
- 운영 서버 배포, DB·설정 변경, 원격 노트북 조작, 실제 쇼핑 요청, 강제 수집 재개는 하지 않습니다.

## 확인한 증거

13:39 KST 서버 조회에서 2번의 1.28.2 원장 6건은 모두 `partial/positive/READ_FAILED`, `pagesRead=1`, `pagesAttempted=2`였습니다. 별도로 `where=all&frm=NVSCTAB` 첫 진입 주소에서도 `UNVERIFIED_PAGE`가 남았습니다.

13:43 조회의 최근 2페이지 실패들은 `trusted` 입력 1회 뒤에도 첫 페이지 주소에 머물렀습니다. 한 건은 `pagingIndex=1&spec=…` 필터 주소로 바뀌었습니다. 보관된 응답 요약에서 일치하는 2페이지 검색 응답은 확인되지 않았습니다. 캡처 보관 한도가 있으므로 이것만으로 실제 요청이 전혀 없었다고 단정하지 않습니다.

오프라인 Chrome에서 실제 `pagerLocate → trustedClickToPage`를 실행하니 페이지 밖의 `<a href="#">2</a>` 필터가 `loose` 분기로 선택됐습니다. 실제 입력 1회가 필터 처리기를 실행해 `pagingIndex=1&spec=…`로 바뀌고 2페이지 요청은 발생하지 않았습니다. 합성 클릭도 같은 잘못된 대상을 고를 수 있으며, 기존 두 경로의 페이지 표식 우선순위가 달랐습니다.

이는 재현된 코드 결함입니다. 해당 운영 시점의 실제 DOM/선택 링크까지 확보한 것은 아니므로 현장의 모든 실패가 이 결함 하나 때문이라고 단정하지 않습니다.

## 설계와 보존 조건

1. `where`는 없거나 정확히 `all`인 경우만 판독기/응답 캡처기에서 허용합니다. 중복·다른 값·필터·검색어/페이지 불일치와 오래된 데이터는 계속 거절합니다.
2. 클릭 후보는 명확한 쇼핑 페이지 표식 또는 현재 검색과 동일한 기본 범위의 목표 페이지 링크로 제한합니다. 문서 전체의 숫자와 `#`, 일반 navigation 영역만으로는 인정하지 않습니다. 표준 입력/합성 입력의 판별 순서를 맞추고, 잘못된 후보가 앞에 있어도 뒤의 정상 후보를 확인합니다.
3. 버튼이 가려졌거나 검증되지 않으면 클릭하지 않습니다. 입력 전송은 이동 성공이 아니며, 실제 결과 검증은 그대로 유지합니다. 클릭 반복·URL 강제 이동·우회 요청은 추가하지 않습니다.
4. 기존 진단 요청의 본문에 페이지별 클릭/주소/판독 근거를 500자 이내 유효 JSON으로 담습니다. 검색어·원문 URL·상품 ID를 본문에 추가하지 않으며, 이전 페이지 클릭 정보가 새 실패에 섞이지 않게 합니다. 진단 요청 수는 늘리지 않습니다.
5. 기존 휴식·감속·서버 배정 대기·미전송함·진단 ACK 처리와 권한은 유지합니다.

검증을 느슨하게 하거나 1페이지 데이터를 2페이지로 인정하는 접근은 채택하지 않습니다. 정확한 버튼을 못 찾으면 부분 결과로 멈추고 진단 근거를 남깁니다.

### 서버 진단 해석

- 자동 진단은 목표/주소 페이지, 클릭 방식·분기·가림, 기존 판독 조건의 통과 여부를 담습니다. `gates.checked=false`이면 판독 조건 전체가 실패한 것이 아니라 해당 단계가 아직 평가되지 않았다는 뜻입니다. `baseline=false`면 이전 자료와 비교할 기준이 없으며 `nextChanged=false`로 남깁니다.
- `tap.page → keyword → source → scope → response → fresh`는 기존 판독 루프에서 해당 조건까지 통과한 보관 항목 수입니다. 가장 최근 유효 응답을 찾으면 순회를 중단하므로 전체 네트워크 요청 통계가 아닙니다. 무관한 p0 HTTP 418을 검색 차단으로 올리지 않습니다.
- 수동 `HUMAN` 진단은 판독 성공을 추정하지 않습니다. 알려진 검색 응답 최신 2건과 나머지 최신 1건을 보존하고 최종 시간순으로 최대 3건을 보냅니다. page/status/age와 출처·범위·응답·현재 검색어 일치 여부만 담으며 미확인 boolean은 null입니다. age는 초 단위, 999 상한입니다.
- 새 진단 본문은 허용 필드만 직렬화하며 최대값 시험에서 수동 374자·자동 394자였습니다. 서버의 500자 절단 전에 유효 JSON으로 완결됩니다. 기존 별도 keyword/href 필드나 기존 STALE/판독 실패 원문 보고까지 익명화했다는 뜻은 아닙니다.
- 수동 진단은 추가 쇼핑 요청 없이 기존 응답을 읽고, 기존 서버 보고 한 건의 ACK를 확인합니다. 보고 성공을 수집 성공으로 표시하지 않습니다.

## 교체 방법 — 먼저 2번 한 대만

1. 수집기를 일시정지하고 기존 확장 폴더를 별도로 보관합니다. 확장을 삭제하지 않습니다.
2. `collector-extension-1.28.3-rc1.zip`을 풀어 현재 등록된 확장 폴더의 같은 이름 파일 8개를 덮어씁니다. ZIP 자체나 한 단계 위 폴더를 등록하지 않습니다.
3. Chrome 주소창에 `chrome://extensions`를 열고 **메타아이앤씨 순위 수집기 카드의 새로고침(↻)** 을 누릅니다. 웹페이지 Ctrl+F5와 다릅니다. 버전 `1.28.3`을 확인합니다.
4. 교체 전에 열려 있던 수집기 전용 쇼핑 탭은 닫아, 다음 정상 진입 때 새 응답 캡처 코드가 주입되게 합니다. 다른 업무용 탭은 닫지 않습니다.
5. 서비스 제한·남은 휴식·서버 일시정지가 있으면 해제하지 않습니다. 제한이 없을 때만 기존 절차로 소량 확인하고 서버에서 `1.28.3`, 새 수집 시각, 실제 `pagesRead >= 2`와 페이지별 증거·저장을 확인합니다.
6. 1번은 유지합니다. 2번에서 정상 이동·순위 대조가 끝나기 전에는 두 대 모두 교체하지 않습니다.

기존 설정과 저장소를 유지하는 교체입니다. 이번 ZIP에는 운영 서버 파일이나 설정이 없으며 서버 재배포도 필요하지 않습니다. 격리 시험 결과만으로 휴식 해제·처리량 증가를 결정하지 않습니다.

## 현장 합격 기준

- 버전 문자열만이 아니라 새 버전의 새 관측이 서버에 도착해야 합니다.
- 2페이지가 필요한 검색어에서 클릭 대상이 정상 페이지 버튼이고 실제 2페이지 자료가 확인돼야 합니다. 첫 페이지 자료를 재사용해 2페이지 완료로 처리하면 불합격입니다.
- 화면의 일반 상품과 기록된 상품·순위를 표본 대조합니다. fixture의 40+40=80, 2페이지 첫 순위 41은 광고/중복 없는 시험 자료의 결과이며 실사이트 모든 화면에 같은 개수를 강요하지 않습니다.
- 가림·제한·미이동은 부분 결과로 남고, 반복 클릭·강제 재개·성공 오표시는 없어야 합니다.
- 다음 오전 10시 완료율은 별도 실제 운영 검증입니다. 이번 패치의 정적/격리 시험으로 처리량을 보장하지 않습니다.

## 남은 검증과 별도 발견

- Windows에서 새 버전의 실제 2페이지 진입·서버 기록·같은 화면의 수동 순위 대조가 필요합니다. 격리 fixture 통과는 현장 합격이 아닙니다.
- 기존 `pageExtract`는 일치하는 문서 안의 가장 긴 상품형 배열을 선택합니다. 가상 자료에서 추천 배열이 검색 배열보다 길거나 동률이면 추천 배열을 선택하는 문제가 재현됐습니다. 실제 운영 자료가 이 경우였다는 증거는 아직 없으며, 이번 클릭/주소 패치와 별개로 실제 자료 구조를 확인해 목록 역할을 검증해야 합니다. 광고 제외 후 14/27/28/38/41개라는 숫자만으로 추천 오인이라고 단정하지 않습니다.
- IP 차단 방지·서비스 제한 해제·오전 10시 전량 완료를 보장하는 변경은 아닙니다. 제한이 뜨면 강제 재개하지 않습니다.
