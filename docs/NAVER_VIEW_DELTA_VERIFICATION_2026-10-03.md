# 관제 화면 유지·변경분 갱신 검증

## 범위와 상태

- 승인: 2026-10-03 대표 “진행해”. 설계 승인에 따른 구현·합성 시험·확인 화면 제공이다. 운영 배포·재시작은 포함하지 않는다.
- 기준: `ac18566`; 구현: `e006869`, 회귀 보완: `19335bb`, 순수 모듈 경계 보완: `1c5fcff`. 기존 운영 제품은 앞선 배포 기록의 `6e4b035`이며 이번 작업에서 운영 서버에 접속하거나 변경하지 않았다.
- 대상: 관제, 이관 현황, 대시보드, 보고서의 저장 자료 GET. 네이버 수집·광고 변경·전산 원본·연결 확정·DB 스키마 변경은 없다.
- 서버는 매번 현재 권한과 저장 자료를 동일 읽기 스냅숏에서 확인한다. 바뀐 응답만 전송하며 기존 DB 집계 계산량 감소를 보장하지 않는다.

## 확인 결과

- 공개 GET·권한·캐시·기존 안전규칙·보고서 시험 48개 로컬 통과. 저장소 오류 로그 2건은 의도한 실패 경로 시험이다.
- 기존 화면 정적 규칙과 보고서 조회/개정 시험 21개 통과(위 시험과 중복되므로 합산하지 않는다).
- 새 실제 엔진→중계→제품 화면 브라우저 시험: 1개 시나리오, 최초 22개 경계/root 5.296초, 검색 초기화 회귀 추가 후 24개 경계/5.089초 통과. 주 작업자의 별도 재실행도 24개 경계/5.442초 통과했다.
- 구버전 `ac18566` 화면에서는 같은 목록 재조회 시 행 DOM을 재생성하는 실패를 먼저 확인했다. 개선 화면에서는 같은 행·검색어·초점·스크롤이 유지된다.
- 추가·금액 감소 정정·제외, 잘못된 변경분의 부분 반영 차단, 전체 응답 복귀, 구버전 응답 호환, 지연 응답/중복 요청, 숨은 화면 재진입, 권한 오류 삭제, 보고서 개정 및 마지막 페이지 소멸, 자정 재확인을 검증했다.
- 독립 서버 검토: 재현 가능한 수정 필요 결함 없음. 별도 합성 150회에서 변경분 병합과 같은 시점 전체 응답이 같았다.
- 전체 회귀에서 찾은 문제도 수정했다. 이관 카드의 같은 서버 조건에서 검색어만 초기화하면 `unchanged` 최적화가 로컬 목록 재표시를 생략했다. 최소 RED(4.329초) 후 카드 클릭의 해당 경우에만 재표시하는 4줄을 추가했고 24개 경계 GREEN으로 확인했다. 변경 없는 반복 클릭의 행 정체성 검사는 그대로 유지한다.
- 기존 권한 구문 검사에서 화면 계층이 담당 행을 직접 펼치는 것을 탐지했다. 검사를 약화하지 않고 `scope.view_cache_identity()`에서 원본과 분리된 식별 자료를 반환하고 기존 `VS.context_key`에서만 직렬화·해시하도록 정리했다. 권한 판정은 기존 함수를 유지한다. 최종 순수 모듈/구문/권한/변경분 시험 139개 통과(다른 부분 시험과 중복). 별도 읽기 전용 최종 검토에서도 발견 0건, 권한·화면 API 시험 121개 통과였다.
- 기존 수작업 DOM 하니스에는 실제 DOM의 `childNodes`/`insertBefore` 동작과 HTTP마다 새 JSON 객체가 생성되는 계약을 보충했다. 보고서 대신 직원 자료를 반환하던 로그인 fixture도 실제 보고서 응답으로 고쳤다. 두 Node 묶음 83개 통과. 제품 코드를 가짜 DOM에 맞춰 완화하지 않았다.
- Chrome 수동 확인: 합성 `가게15` 추가→목록 갱신→`가게11` 잔액 43,210원 정정→`가게15` 제외를 제품 UI에서 확인했다. 운영 자료가 아니다.

## 합성 응답 전송량

관제 한 행 정정은 3,488B, `upsert=1`, `removed=0`이었다. 요약/이슈 등 목록 외 필드는 현재 값으로 교체하므로 전체 응답이 항상 190B라는 뜻은 아니다. 운영 계정 전체의 속도 개선 배수나 네이버 수집 성능으로 해석하지 않는다.

## 보관·권한 경계

- 서버 캐시: 직렬화 자료 16MiB/128개/300초. DB 연결·토큰을 보관하지 않으며 잠금으로 상한을 지킨다.
- 화면 캐시: 창 메모리 내 최대 8개/약 4MiB/10분. 영구 업체 자료 저장 없음. 기존 세션 토큰 저장은 유지한다.
- 인증/조직/범위/날짜 오류에는 업체 자료와 DOM을 제거한다. 일반 통신 실패는 이미 검증되어 보이던 같은 범위만 실패 문구와 이전 확인 시각을 붙여 유지한다.
- 응답은 `no-store`. 커서는 권한이 아니다. 손실·만료·다른 사용자/로그인/범위/조직/날짜 커서는 전체 응답으로 복귀한다.
- 화면을 다시 여는 것은 저장 자료 조회이며 네이버 수집 요청이 아니다. 합성 시험의 외부 요청·제품 업무 쓰기 0건.

## 환경 구분과 전체 검증

- Mac 기본 파일 저장소는 기존 `open_writer` 잠금 단계에서 실패했다. 제품 잠금·WAL·권한 정책을 완화하지 않았다.
- 로컬 브라우저 시험/시연은 별도 테스트 전용 메모리 SQLite이며 실제 파일 WAL의 증거가 아니다.
- 첫 Linux 전체 회귀 [37102998642](https://github.com/metainchelp-boop/metainc-ad-dashboard/actions/runs/37102998642): 실제 파일 DB 스냅숏 2개 통과. 구버전 UI 기대 2건, 실제 검색 초기화 1건, 권한 계층 구문 1건, 기존 DOM/응답 fixture 2건 실패를 확인했다. 수집/재시도/SSH/nginx/이미지 검사는 통과했다.
- 두 번째 Linux 전체 재검증 [37103692674](https://github.com/metainchelp-boop/metainc-ad-dashboard/actions/runs/37103692674): 실제 파일 DB·전체 브라우저·기존 기능은 통과했다. 순수 권한 모듈의 `hashlib`/`json` 의존성 금지 검사 1건만 실패해 위처럼 책임을 분리했다. 허용 목록이나 검사 기준은 바꾸지 않았다.
- 최종 `1c5fcff9f5c9a48c88baafd35f74407c3b8dd463` Linux 전체 재검증 [37104161216](https://github.com/metainchelp-boop/metainc-ad-dashboard/actions/runs/37104161216)은 2026-10-03 15:51 KST 성공했다. 주요 4묶음은 1,251+395+181+84=1,911개 대상 중 1,909개 통과·기존 환경 제외 2개·실패 0개다. 제외는 비루트 소유자 변경 시험과 namespace 안 Compose CLI 부재 검사이며, 원문/이미지 격리 검사는 별도 수행했다.
- 새 실제 파일 DB 스냅숏 2개와 변경분 브라우저 24경계 시나리오도 최종 Linux 회귀에서 통과했다. 별도 SSH/nginx 10개, 엔진 이미지 47개, 중계 이미지 4개 중 3개 통과·동일 Compose CLI 검사 1개 제외, 컨테이너 빌드/격리 확인 단계까지 성공했다. 주요 1,911개에 이 별도 검사를 중복 합산하지 않는다.
- 로컬 메모리 하니스에서도 기존 대시보드와 이관 현황 브라우저 시나리오가 각각 통과했다. 기존 종합 화면 시나리오는 브라우저 검사 후 최종 파일 바이트 검사에서 메모리 fixture에 파일이 없어 종료했다. 이 검사를 우회하지 않고 Linux 파일 DB 결과로 판단한다.
- 예전 회귀시험의 ‘일반 통신 실패 시 화면 전체 제거’ 기대는 승인된 ‘같은 범위의 이전 자료 유지+실패 표시’로 갱신한다. 권한 실패 시 자료 삭제 검증은 유지·강화한다.
- 운영 반영과 실서비스 검증은 별도 배포 승인 후 진행한다. 이 문서는 운영 검증 완료 기록이 아니다.

## 확인 화면

`tools/naver-view-delta-demo.py`는 loopback에만 열리는 시험 화면이다. 실제 제품 엔진·중계·화면과 합성 SSO/메모리 DB를 사용한다. 실행 시 출력되는 주소로 접속하며 최대 1시간 뒤 자동 종료한다. 제어 단추는 시험 자료만 바꾸고, 제품의 `목록 새로고침`으로 반영을 확인한다. 시험용 경로는 제품 서버에 추가하지 않았다.
