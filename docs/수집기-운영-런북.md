# 수집기 중지·미전송 복구 런북 (코덱스 1.22.0 운영 절차 이식판 · 2026-09-22)

> 대상: 로직분석 관리자·수집 노트북 담당자. 근거 화면 = 로직분석 「📊 쇼핑 순위 추적」 맨 위 **🧭 수집기 운영** 패널 + 확장 팝업.
> 원문(코덱스 `COLLECTOR-RECOVERY-RUNBOOK.md`)의 절차를 **우리 상태 이름·우리 버튼**으로 다시 적었다. 여기 없는 조치는 하지 않는다.

## 1. 먼저 볼 것 (순서대로)

1. **운영 패널 상단 타일** — 오늘 완료/남음 · 어제 완료 · 상품 연결 확인 필요 · 대기 요청 · 전체 제어.
   「미확인」은 **못 잰 것**이지 0 이 아니다. 미확인이 뜨면 서버 로그(진단 `live_check=on`)부터 본다.
2. **기계 표** — 기계마다 마지막 신호 시각·상태·📤 미전송. 15분 넘게 신호가 없으면 「⛔ 신호 끊김」 = 크롬/확장이 안 도는 것(일시정지·캡차 쉼과 다르다).
3. **📤 미전송** 은 **그 기계의 마지막 보고**다. 5분이 지나면 「오래된 보고」로 표시된다. 「보고 없음」은 v1.26.0 미만 확장, 「확인 불가」는 형식 오류, 「세션 바뀜」은 브라우저 재시작 뒤 새 보고 대기.
4. 완료 수와 **실제 측정 시각**은 다른 축이다. 미전송 0 · 재개 승인 · 최근 신호 어느 것도 「오늘 순위가 정상」의 증거가 아니다 — 순위 화면의 날짜를 본다.

## 2. 상태·사유별 조치

| 화면에 보이는 것 | 담당자가 할 일 | 하면 안 되는 것 |
|---|---|---|
| **📤 미전송 n건**(검토 필요 0) | 서버가 살아 있으면 5분 안에 스스로 줄어든다. 안 줄면 팝업 「📤 미전송 다시 보내기」 1회. | 확장 삭제·재설치(보관함이 같이 지워진다) |

## 3. 검토 후 전체 재개

1. 필요하면 먼저 **⏹ 전체 중지** — 새 회차만 막는다. 이미 시작한 키워드는 그 회차가 끝난다.
2. 각 기계의 중지 원인·미전송·캡차 쉼을 확인한다. 팝업의 일시정지는 별개로 확인한다.
3. 패널 **새로고침** → 내용을 읽고 **「원인을 검토했습니다」 체크** → **▶ 검토 후 전체 재개** 한 번.
4. 「처리 여부를 확인하지 못했습니다」가 뜨면 자동 재전송하지 않는다. 새로고침으로 현재 상태를 본 뒤 필요하면 다시 누른다.
5. 재개 승인은 가동 완료가 아니다. 각 기계는 다음 1분 알람에서 반영하고, 캡차 쉼·기계별 상한은 그대로다.
6. 재개 뒤 **다음 보고의 미전송 수와 오늘 완료 수**를 함께 본다. 미전송이 줄고 완료가 늘어야 정상이다.

## 4. 개발자에게 넘길 최소 정보

실패 단계(수집/업로드/보관함) · 상태 문구 · 마지막 신호 시각 · 마지막 정상 측정 시각 · 확장 버전 · 진단 파일(팝업 「🧾 진단 파일」 — 토큰·검색어·상품·기계 식별자·원문은 들어 있지 않다).
서버 쪽은 진단 워크플로 `debug-rank.yml` `live_check=on`(기계별 신호 · v2 원장 · 관측 원장) 을 돌려 함께 본다. **런 로그에 검색어·업체명이 찍히면 읽은 뒤 지운다.**

## 5. 이 런북이 다루지 않는 것

퍼즐 자동 해제 · IP/계정 교대 · 다른 노트북으로 같은 키워드 우회 재수집 — 전부 하지 않는다(이 저장소 규칙). 미전송 보관함은 **기계 안**에만 있고, 확장 삭제·크롬 프로필 삭제와 함께 사라진다.
