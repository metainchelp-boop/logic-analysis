# 최초 실데이터 연결 — 2026-10-01

## 승인과 범위

대표 요청: 광고주 계약 목록과 운영 수집 데이터를 가져와 운영되는 화면을 직접 보며 개선한다.
이미 배포된 읽기 전용 관제에 실제 목록·계정 연결·운영 GET 수집을 반영한다.
ALL/TEAM/MINE 범위, 업무 POST 차단, 자동 입찰·알림·ERP 공유지표 OFF는 유지한다.
기존 광고센터·로직분석·콘텐츠 스튜디오 서비스는 수정하거나 재시작하지 않는다.

## 원인과 확인

최초 단계 목록의 예상 940건 기준은 과거 6개 단계 모집단이었다.
현재 7개 단계 조회는 계약만료를 포함하므로 최초 변화량 검사가 반영을 보류했다.
실제 보류 원문을 읽기 전용 감사하여 중복, 단계 충돌, 조직 소유정보 연결,
유효기간과 정확한 저장 원문 SHA-256을 확인한 후 그 원문만 수락한다.

## 선택한 방식

공개 POST 제한을 해제하지 않고, 서버 관리자가 고정 경로에 놓는
root:10001 / 0440 단일 실행 요청을 시작 시점에 소비한다.
요청 ID·보류 ID·원문 해시·건수·대표 승인자·당일 만료·최대 600초를 고정한다.
배타적 시작 기록 → 기존 DB 스냅샷 → 보류 재검증·수락 → 계정 연결 GET →
실제 현재 시각의 요청 수집 순으로 실행하며, 완료/부분완료를 별도 기록한다.
재시작으로 같은 요청을 자동 재실행하지 않는다.

예약 수집의 06:30–08:00 창, 하루 최대 3회, 재시도 대기, 대상 적격성,
만료 후 14일 제한, 단일 쓰기 담당 스레드, 전송 속도·키 오류 안전장치는 보존한다.
가짜 아침 시각을 기록하거나 연결이 모호한 계정을 임의 확정하지 않는다.

## 배포·검증

새 소스의 Linux 단위·통합·브라우저 검증을 통과한 뒤 기존 서버 공개키로 봉인한다.
서버에서 기존 실행 자격 4개가 동일한지 확인하고 새 격리 이미지를 먼저 준비한다.
기존 기준선과 전용 서비스 유닛 원문을 확인한 뒤 관제 2개 서비스만 교체한다.
실패 시 그 2개 유닛·이미지만 되돌리고 수집 DB는 덮어쓰지 않는다.

완료 판단은 화면 배포 성공과 구분한다. 실제 계약 수, 연결 상태, 점검 대상·성공·
미완료 건수와 시각을 확인하고, 대표 SSO로 목록과 상세를 확인한다.
수집 미완료 또는 아직 자료 미반영 상태를 정상·0건 완료로 표시하지 않는다.
