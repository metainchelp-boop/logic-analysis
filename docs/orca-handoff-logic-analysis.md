## 5. 일하는 방법 (클라우드에서 쓰던 방식 그대로)

**운영 서버 보기 — 진단 워크플로(읽기 전용)**
- 서버에 직접 들어가지 않습니다. GitHub Actions `debug-rank.yml`을 **진단 가지 `diag/ai-and-batch`** 로 손 실행합니다(⛔ 이 가지는 머지 금지).
  ```bash
  gh api -X POST repos/metainchelp-boop/logic-analysis/actions/workflows/debug-rank.yml/dispatches \
    -f ref=diag/ai-and-batch -f 'inputs[ai_batch]=on'
  ```
  - `ai_batch=on`: 아침 분석 진행 기록 · 날짜별 분석 줄 수 · AI 모델 설정 · AI 실패 줄 · 오류 기록 · 컨테이너 상태
  - `chat_probe=on`: 실제 AI 채팅을 일반 키워드 하나로 1회 돌려 답을 확인
  - 출력은 작업 기록의 ` out: ` 줄입니다. 읽은 뒤 **실행 기록을 지웁니다**(공개 저장소): `gh api -X DELETE repos/metainchelp-boop/logic-analysis/actions/runs/<run_id>/logs`
  - 입력 칸은 25개 한도 중 24개를 씁니다. 새 진단은 기존 입력 안에 구간을 더하는 쪽으로 합니다.
- 진단 출력에 업체명 · 키워드 · IP 를 찍지 않습니다. 찍혔으면 읽은 즉시 실행 기록을 지웁니다.

**배포**
- `main` 푸시 = `deploy.yml`(시험 게이트 약 50단계 → 빌드 → 컨테이너 교체 → 헬스체크 → 실패 시 자동 되돌림). 대표님 「배포하자/배포해」 뒤에만 합니다. 「권고대로해/고쳐」는 구현 승인이지 배포 승인이 아닙니다.
- `**/*.md`만 바뀐 푸시는 배포가 돌지 않습니다(진단 워크플로 파일들도 제외 목록에 있음).
- 새 시험은 `deploy.yml` 게이트에 단계로 등록하고, 머지 전에 **게이트의 시험 단계를 로컬에서 전부** 돌립니다(새 시험만 돌리고 통과라 하면 안 됨).
- 배포 뒤 같은 차례에: ① FE 저장소에 개발 이력 글 하나(`src/history/entries/YYYY-MM-DD-HHMM-sales-…md` · 업체명 · 금액 · 직원 이름 · 내부 코드 금지 · 시각 = 배포 시각) ② 섹션 소식판(FE `section-feed` 가지 `SECTION_BOARD.md`) ② 줄 ③ 지식 창고 `일지/날짜.md` 「## 세션 기록」 한 줄 · 결정 대기 ↔ 결정 기록.
- 배포 확인 = deploy 실행 `success` + 진단 출력(컨테이너 기동 시각 · 새 코드 표지 · 오류 0). HTTP 401 · 200 같은 응답으로 「새 코드가 올라갔다」고 하지 않습니다.

**git**
- 커밋은 늘 `git -c user.name=metainchelp-boop -c user.email=metainchelp@gmail.com commit …`(merge · rebase · cherry-pick 도 커밋을 만듭니다).
- 커밋 · PR 본문 · 코드에 AI · 모델 이름을 넣지 않습니다. PR 생성 도구가 붙이는 서명 줄은 지웁니다.
- 강제 푸시하지 않습니다. 원격 가지가 앞서 있으면 받아서 합친 뒤 올립니다. 머지 전 `git fetch`(로컬 `origin/main`이 낡아 있던 적 있음).

**대표님께 드리는 말**: 한국어 · 격식체 · 세 칸(현재 상황 / 제가 한 일 / 대표님께서 하실 일). 확인 못 한 것은 「확인하지 못했습니다」, 짐작은 「추정」. 직원은 이름, 업체는 업체명으로(저장소 · 문서에는 쓰지 않음).

## 6. 이번에 밟은 함정 (11/17~18 · 다시 밟지 않기)

- anthropic SDK 2.x 는 `httpx` 대신 `httpx2`를 씁니다. 시험에서 가짜 전송을 끼울 때 `import httpx2 as httpx`(없으면 httpx).
- 시험이 **모든 예외**에 「건너뜀」을 하면 문법 오류까지 숨깁니다(실제로 `scheduler.py` 괄호 오류가 숨었다). 의존성 없음(`ImportError`)일 때만 건너뛰고, 따로 `py_compile`로 확인합니다.
- 진단 yml 안의 heredoc 파이썬은 블록 들여쓰기(12칸)를 지킵니다. 1칸에 두면 YAML이 깨집니다.
- 검색광고 keywordstool 은 `hintKeywords`에 공백이 있으면 400 입니다.
- 컨테이너는 배포마다 바뀌어 그전 앱 기록이 사라집니다. 지난 사고 원인은 DB 기록(`daily_batch_runs` · `client_analyses`)과 진단으로 봅니다.
- 스케줄러(APScheduler)는 파일 잠금으로 uvicorn 일꾼 5개 중 1개에서만 돕니다. uvicorn 0.30.6 은 5초 안에 응답 없는 일꾼을 다시 띄웁니다(아침 분석 멈춤의 후보 · 추정).
- `.env`의 모델 값은 `deploy.yml`의 고침 단계가 다룹니다. compose 에 `CLAUDE_MODEL`을 넣지 않습니다(종전 규칙).
- 대표님 질문의 축과 데이터의 축이 다를 수 있습니다 — 「이름으로 판정하지 않는다」 절을 지킵니다(경로 · 표 · 칸 이름만 보고 단정 금지 · 스키마 추측 금지).
