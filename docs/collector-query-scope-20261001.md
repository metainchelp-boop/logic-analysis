# 검색 후 멈춤·진단 수신 확인 수정 — 1.28.2-rc1

## 기준과 범위

- 기준 커밋: `02c0ba989bd68d846bb37b67fc59c8137f9276b0`, 확장 `1.28.1-rc1`.
- 사용자 승인: 확인한 주소 검증 오류와 진단 전송 확인 오류를 수정하고 교체 ZIP을 제공.
- 서버 배포·DB 변경·수집 설정 변경·노트북 원격 교체를 수행하지 않습니다. 신규 권한·도메인·프로그램 설치도 없습니다.
- 이전 1.28.1 후보의 휴식 보존, 중앙 배정 대기·재개, 순위 증거 검증은 유지합니다.

## 수정 근거와 동작

### 정상 검색 주소를 거절하던 오류

서버에 남은 1.28.1 진단의 쇼핑 주소에는 `prevQuery=<이전 검색어>&vertical=search`가 포함되어 있었습니다. 기존 `pageExtract.matchingQuery()`는 두 항목을 모두 미허용 항목으로 분류해, 정상 목록과 일치하는 최신 데이터가 있어도 `UNVERIFIED_PAGE`로 거절했습니다. 실제 주소 형태를 실제 판독 함수에 넣은 격리 시험으로 재현했습니다.

- 판독기와 수동 응답 복사기 `net_tap` 양쪽에 같은 허용 규칙을 반영했습니다.
- `prevQuery`는 이동 부가정보로 허용하지만 현재 검색어 검증은 `query`와 계속 대조합니다.
- `vertical`은 없거나 정확히 `search`인 경우만 허용합니다. 빈값·다른 값·중복 항목은 거절합니다.
- 다른 검색어·페이지, 비기본 정렬/상품 범위, 알 수 없는 필터, 오래된 응답, 변하지 않은 라우터/초기 데이터는 여전히 거절합니다.
- 요청 주소·횟수·수집 속도·페이지 수를 늘리거나 강제로 스크롤하는 변경은 없습니다.

이 오류는 '검색하고 목록에서 멈춤'을 설명하는 확인된 원인입니다. 실제 사이트의 모든 화면 구조와 Windows 상태까지 해결됐다는 의미는 아닙니다.

### 진단 전송의 성공 표시

기존에는 수동 진단 버튼에 즉시 성공을 반환하고, 서버 HTTP 상태나 저장 응답을 확인하지 않았습니다. 이제 서버의 HTTP 성공과 JSON `success: true`를 모두 확인한 뒤에만 성공을 표시합니다. 인증키 누락·열린 쇼핑 탭 없음·페이지 판독 실패·HTTP 오류·서버 응답 미확인은 실패/미확인으로 구분합니다.

서버 응답 대기는 제한하며 자동 재전송하지 않습니다. 서버가 저장한 직후 응답이 유실된 경우도 있으므로, 시간 초과·연결 오류를 '서버에 저장되지 않음'으로 단정하지 않습니다. 자동 진단 실패는 수집기에 예외를 던지지 않습니다. 이 버튼은 이미 열린 화면을 읽어 기존 사내 서버로 전송하며, 네이버 검색 요청을 새로 보내지 않습니다.

## 교체 방법 — Windows 2번 노트북부터

1. 수집기에서 **일시정지**하고 기존 확장 폴더를 복사해 보관합니다. 기존 확장을 제거하거나 쿠키·로컬 저장소를 지우지 않습니다.
2. ZIP을 풉니다. `manifest.json`이 보이는 8개 파일을 **현재 설치에 사용 중인 같은 확장 폴더**에 덮어씁니다. ZIP 자체를 Chrome에 넣는 방식이 아닙니다.
3. 주소창에 `chrome://extensions`를 입력합니다. 해당 '메타아이앤씨 순위 수집기' 카드의 **새로고침(↻)**을 누르고 세부정보/팝업에서 **1.28.2**를 확인합니다. 페이지의 F5/Ctrl+F5와 확장 카드 새로고침은 다릅니다.
4. 구버전이 주입된 수집기 전용 쇼핑 작업 탭은 닫습니다. 다음 정상 수집 시작 시 새 탭에 새 캡처 코드가 주입되게 합니다. 다른 사람이 사용하는 쇼핑 탭은 건드리지 않습니다.
5. 접근 제한·캡차·차단 휴식이 있으면 강제 재개하지 않습니다. 제한이 없고 기존 대기 조건이 허용할 때 2번 노트북에서 먼저 제한적으로 확인합니다. 1번 노트북은 동시에 교체하지 않습니다.

확장을 삭제하지 않고 같은 폴더를 덮어써 기존 확장 ID·토큰·미전송함·휴식 상태를 보존합니다. 문제가 있으면 다시 일시정지한 뒤 보관한 이전 폴더의 파일을 같은 위치에 복원하고 확장 카드를 새로고침합니다. 롤백은 이번 원인을 해결하지 않으므로 무작정 재수집하지 않습니다.

## 현장 합격 기준

- 2번 노트북의 서버 heartbeat에 확장 버전 `1.28.2`가 보입니다.
- 정상 목록에서 첫 페이지 판독이 진행되고, 2페이지 확인이 필요한 검색어에서 한 번의 이동 뒤 실제 2페이지 상품과 기록된 순위가 일치합니다. 목표를 첫 페이지에서 모두 찾으면 2페이지로 이동하지 않는 기존 조기 종료는 정상입니다.
- '이 화면 응답 보내기'를 눌렀을 때 서버 저장 성공/실패/미확인이 분명하고, 성공 시 서버에 해당 버전의 새 `HUMAN_PROBE` 진단이 보입니다.
- 접근 제한이 나타나면 시험을 중단하고 기존 휴식을 유지합니다. 반복 새로고침이나 강제 수집으로 시험하지 않습니다.

Windows 현장 검증, 실 네이버 차단율, 하루 처리량, 오전 10시 전량 완료는 이 ZIP의 오프라인 시험으로 보장하지 않습니다. 기존 후보에 포함됐던 서버 관측 검증 변경도 확장 ZIP만으로 배포되지 않습니다.

## 검증 결과

- 실제 판독/캡처 함수에서 수정 전 주소 재현 시험 실패를 확인한 뒤 수정 후 통과했습니다.
- 확장 `.test.js` 19개 파일 전체 통과: Node가 집계하는 46개 시험 단위, 실패 0. 파일 내부 기존 assertion 수와는 다른 집계입니다. 새 주소 범위 시험 9개와 진단 ACK 시험 10개를 포함합니다.
- 격리 Chrome fixture 8개 통과: 기존 5개 + 관측된 부가정보를 포함한 응답 캡처/라우터/HTTP418 3개. 정상은 1~80위 연속 기록, 두 번째 장 첫 상품 41위, 페이지 클릭 1회, 제한은 확인된 첫 40개만 부분 보존합니다.
- 관련 backend 시험 12개 파일 통과: collector_coord, collector_observation, collector_board, done_when_found, codex_port_3, codex_port_4, collector_v2_wire, collector_settings, product_match_identity, rank_guard, block_report, db_busy. 최소 DB fixture의 기존 테이블 누락 경고는 있으나 실패는 없습니다. 서버 실행 코드는 이번 변경에서 수정하지 않았습니다.
- 주소 규칙과 ACK 흐름에 대한 별도 읽기 전용 검토에서 새 결함을 발견하지 못했습니다. 이 결과는 Windows·운영 서버 수신 시험의 대체가 아닙니다.
- 변경 JS 구문 검사와 `git diff --check` 통과. 기존 권한/도메인과 수집 제한은 유지합니다.
- 두 신규 시험은 기존 CI 검사 단계에도 등록했습니다. workflow의 배포 트리거나 대상 브랜치는 변경하지 않았습니다.
