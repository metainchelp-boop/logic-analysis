# 수집기 실기기·제한 운행 점검표 (코덱스 1.22.0 `DEVICE-ACCEPTANCE` 이식판 · 2026-09-22)

> 4·5차(미전송 보관함 · 중앙 배정 · 운영 패널)를 **실제 두 노트북**에서 확인할 때 쓰는 표. 오프라인 시험(게이트 42+)은 통과했지만
> **아래는 전부 미실시**다 — 실기기에서 본 뒤 「진행 가능 / 보완 후 재시험 / 보류」를 적는다. 시험이 아니라 운영 중에 자연히 확인되는 항목도 있다.

## 시작 전 확인

- 시험용/운영용 구분 · 담당자 · 시간대 · 두 노트북 접근 방법(원격 없음 — 대표가 직접).
- 각 기계의 확장 버전(팝업 상단) · 기계 번호/대수 · 토큰 저장 여부. 토큰·쿠키·프로필은 옮기지 않는다.
- 서버 배포 런(success) · 부팅 로그 · 진단 `live_check=on` 이 표 3종(heartbeat · coord · observations)을 읽는지.
- 동일 회선 여부 · 시간당 상한(40) · 기계별 상한(10) — 시험 수치를 운영값으로 올리지 않는다.
- 지금 멈춘 기계가 있으면 중단 시각·상태·마지막 정상 측정·미전송 수를 먼저 적는다. 원인 모른 채 재시작하지 않는다.

## 실기기 시험 (각 행: 시각(KST) · 사전 상태 · 절차 · 기대/실제 · 판정)

| 시험 | 반드시 볼 결과 | 현재 |
|---|---|---|
| 두 기계 등록·배정(서버 스위치 켠 뒤) | 서로 다른 기계 ID · 같은 키워드 이중 배정 0 · 기계를 늘려도 전역 상한 불변 | 미실시 |
| 회차 중 절전/정상 종료 | 임대가 600초 뒤 서버에서 회수돼 다시 배정 · 재가동 후 옛 임대로 업로드 시 LEASE_MISMATCH 경고만(수집분은 저장) | 미실시 |
| **업로드 중 회선 단절·서버 재기동** | 팝업 「📤 미전송 n건」 · 서버 복구 뒤 5분 안에 0건 · 서버 관측 원장 중복 0 · **재전송 때문에 새 검색 0** | 미실시 |
| 브라우저/PC 재시작 | 기계 ID 유지 · 미전송 보관함 유지(IndexedDB) · 살아있음 신호에 uploadSummary | 미실시 |
| 서버가 본문을 거절(4xx)한 경우 | 「검토 필요」로 격리 · 자동 재시도 0 · 「검토 후 비우기」로만 삭제 | 미실시 |
| 보관함 상한(100건) | 101번째부터 실패로 세고 보관하지 않음 · 팝업 경고 | 미실시 |
| 중앙 중지 → 검토 후 재개 | 중지 뒤 새 회차 0 · 체크 없이 재개 요청 0 · 재개 뒤 1분 안에 각 기계 반영 | 미실시 |
| 한국 자정·PC 시계 오차 | 순위 날짜는 서버 기준 · 어제 값이 오늘로 안 들어감(순서 가드 `collector_rank_projections`) | 미실시 |
| 운영 패널 값 대조 | 패널 「오늘 완료」= 진단 `collected_serp` 당일 키워드 수 · 기계 표 = heartbeat 표 · 「미확인」이 뜨는 칸 0 | 미실시 |

디스크를 실제로 채우거나 운영 DB 를 손상시키는 시험은 하지 않는다. 회선 단절은 노트북 Wi-Fi 끄기로 흉내 낸다.

## 제한 운행 판정 지표 (2~3일 관찰)

| 지표 | 원칙 |
|---|---|
| 유효 일일 완료율 | 분모 = 유니버스 전체(미해결·실패를 몰래 빼지 않는다) · 분자 = 그날 저장된 키워드 |
| 순위 정확도 | 사람이 같은 시각·같은 조건으로 본 표본 5개와 대조 · 검증 안 된 값은 미확인 |
| 갱신 지연 | 실제 측정 시각 → 08:40 전산 캐시까지 |
| 불필요한 동작 | 같은 키워드 하루 2회 이상 수집 · 재전송 중 새 검색 |
| 중지·복구 | 원인별 중지 횟수 · 감지 → 조치 → 재개까지 시간 |
| 저장 무결성 | 원문 손실 · 관측 중복 · 날짜 혼합 · 미승인 삭제 각각 0 |

최종 결정은 **진행 가능 / 보완 후 재시험 / 보류**로 적는다. 지금 결정: `보류 — 실기기 미실시`.
