# 관제 접속·탭 지연 수정 — 2026-10-08

운영 브라우저에서 로그인 교환 973ms 다음 /me가 30,050ms 뒤 504로 실패했고, 재조회도 30,033ms 504였다. 같은 운영25dc24d의 제한된 별도 읽기 프로파일은 staff_counts 22.81초 도중 25초 예산에 도달했다. 내부 구조 요약14.19초에는 관리 매칭6.63초가 포함된다. 중첩 시간은 합산하지 않는다. CPU 0.5 quota 및 throttling과 512MiB 부근 메모리를 확인했다. 이 진단은 인증된 HTTP나 같은 엔진 GIL의 계측이 아니다.

## 변경

- 직원별 계정 수는 현재 매칭·모호성·담당 범위만 계산한다. 성과/구조/이탈/잔액/coverage 이력을 읽지 않는다. board와 현재 매칭 판정 함수를 공유한다.
- 한 요청의 같은 입력 매칭은 management_store 기존 메모 경계에서 한 번만 수행한다. 원천 최신성·권한은 매번 다시 판정한다.
- 성과 및 이전 성공 요약에서 사용하지 않는 progress_json/campaigns_json 열을 읽지 않는다. WHERE, ORDER, 반환값, schema11은 그대로다.
- 같은 탭 연타는 진행 중 GET 하나에 합치고, 이탈·담당 변경·비활성 전환은 불필요 GET을 취소한다. 실제 패널 변경과 재진입의 서버 재검증 및 권한 실패 purge를 유지한다.
- 상세점검 RUN_ABORT는 허용 코드/원인/호출수/경과만 로그에 기록한다. 네이버 요청 한도·재시도·원장 상태는 변경하지 않는다.

## 검증

실제 WSGI /me의 상세 이력 읽기 금지, 원래 board 기반 담당 수 동등성, 변경 전 SELECT *와 반환값 동등성 시험을 실패부터 확인했다. 현재/부재 계정, 숨김/미확인 단계, 만료/환불, 실패/낡은 원천, main/sub/prev, 좁힌 세션, 비관리/퇴사, 다계정 범위를 검사했다.

Linux 기존 Python3.12.14·네트워크 차단 컨테이너에서 관련130개(실제 Chromium 화면 회귀 포함), 별도 매칭/권한/쓰기143개가 통과했다. SQLite projection 추가62개도 별도로 통과했다. FE 실제 Chrome 전용11개/기존Node45개 통과. 시험 개수는 묶음별이며 중복 합산하지 않는다.

전체 CI의 첫 실행에서 브라우저 시험 도구 2개가 변경된 요청 취소 계약을 반영하지 못해 실패했다. 보고서 VM에 표준 AbortController를 주입하고, 이전 범위 조회는 응답 대신 ERR_ABORTED를 확인하도록 고쳤다. 이전 범위 정보가 화면에 섞이지 않는 DOM 검증은 유지했다. 같은 Linux 시험 2개에서 수정 전 실패와 수정 후 통과를 확인했다. 제품 파일 추가 변경은 없다.

합성 JSON 부하에서 필요한 열만 읽을 때 메모리 비용 감소와 전체 반환값 동등성을 확인했다. 실제 운영 개선폭은 배포 후 브라우저와 프로파일로 확인해야 한다. 이 문서는 배포·운영 해결 증거를 대신하지 않는다.
