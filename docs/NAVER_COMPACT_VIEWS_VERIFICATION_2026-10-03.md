# 이관 분류 전환·상향 목록 접기 검증

## 범위

- 대표 2026-10-03 “응 진행해” 승인. 기준 `d446693`이며 [승인 설계](superpowers/specs/2026-10-03-transfer-view-switch-design.md)에 따른 화면 개선이다.
- 이관 현황은 `전산 실관리·누락 대조`를 기본으로, `이관 광고 계정 전체`와 버튼으로 전환한다. 공통 요약 카드와 새로고침을 유지하며 검색·필터는 왕복 시 유지한다. 요약 카드는 계정 분류를 열고 기존 필터 규칙을 적용한다.
- 관제 `나에게 올라온`은 기본 접힘이며 현재 필터 기준 건수는 보인다. 펼치기·접기는 읽음·확인 중·해결 처리가 아니다.
- 제품 변경은 `backend/naver_page/`의 화면 파일 3개로 제한한다. API·권한 판정·수집 일정·DB 스키마·전산 원본·광고 설정 변경은 없다. **운영 미반영**이며 이번 차례에 운영 접속·배포·재시작·재수집은 하지 않는다.

## 검증 진행

- 첫 RED: 기존 화면의 이관 계정 영역이 초기부터 보이는 실패를 실제 엔진→중계→브라우저에서 재현했다(2.449초).
- 첫 GREEN: 한 영역만 표시, 현재 권한 재확인 전 가림, 키보드 전환, 왕복 검색 유지, 요약 카드 자동 전환 5경계를 확인했다(2.125초).
- 상향 목록도 기본 펼침 실패를 먼저 확인하고 접힘 구현 후 통과했다(2.440초).
- 기존 Node 83개, 변경분 갱신 브라우저 24경계, 기존 이관 브라우저 시나리오는 탐색 버튼을 명시한 후 통과했다. 기존 업무·권한 단언은 삭제하지 않았다.
- 화면 정적 규칙 9개, JavaScript 문법 검사를 통과했다.
- 최종 제품 수정 후 주 작업자도 Node 83개를 별도로 다시 실행해 통과했다(0.532초).
- 신규 실제 엔진→중계→Chromium 시나리오 22경계를 통과했다(4.925초). 초기 분류, 권한 재확인 전 가림, 키보드 전환, 검색·필터 왕복, 카드 자동 전환, 기본 접힘, 새 항목 추가 시 접힘 유지, 변경분 갱신 중 버튼 초점, 필터 0↔여러 건, 업체 상세 왕복, 숨은 링크 탐색 제외, 범위 전환, 두 분류의 1440/1024/390폭 넘침0, 일반 통신 실패와 권한 실패, 늦은 응답, 로그인 종료·교체, 날짜만 바뀐 경우 선택 유지, 영구 업체자료/표시선택 저장 없음까지 포함한다. 페이지 오류·외부 요청·제품 업무 쓰기는 모두 0건이다.
- 최종 Linux 결과는 완료 후 아래에 기록한다. 로컬 메모리 시험을 파일 DB 검증으로 대신하지 않는다.

## 직접 화면 확인과 환경

- Chrome에서 두 분류 단독 표시와 상향 목록 4개 항목의 접기·펼치기를 직접 확인했다. 상향 판정은 합성 DB의 미확인 주의 이슈를 제품 엔진이 판단한 결과이며 임의 응답으로 화면만 꾸민 것이 아니다.
- 최종 제품 소스를 다시 읽은 Chrome에서 390폭의 분류 버튼·새로고침 줄바꿈과 가로 넘침 없음(문서 폭375≤창390)을 확인하고 임시 창 크기를 원복했다.
- 독립 표준 검토 결과 확정 위반 0건이다. CSP·텍스트 렌더·서버 권한은 그대로이며 새 영역은 GET 성공 후에만 공개한다. 시연은 합성 자료에 한정된다. 이 결과는 정적 검토이며 운영 검증은 아니다.
- 표시 선택은 같은 화면 인스턴스의 목록 새로고침·필터·메뉴 왕복에 유지된다. 브라우저 F5는 기본값으로 시작하며 업체 자료나 표시 선택을 새 영구 저장소에 보관하지 않는다.
- `tools/naver-view-delta-demo.py`는 기존 변경분 시험에 상향 이슈 fixture를 더해 시연한다. loopback·합성 SSO·메모리 SQLite이며 실제 계정/운영 DB를 사용하지 않는다. 최대 1시간 뒤 종료한다.
- Mac의 기존 파일 잠금 제약 때문에 로컬 브라우저는 시험 전용 메모리 SQLite를 사용한다. 제품 파일 잠금을 완화하지 않았으며 실제 파일 DB 결과는 Linux 검증과 구분한다.
- 캡처는 로컬 `outputs/`에 두고 커밋하지 않는다. 화면 수치·업체명·날짜는 시험 자료다.
