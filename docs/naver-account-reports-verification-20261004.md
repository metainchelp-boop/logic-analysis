# 계정별 보고서 개편 구현·검증 기록

2026-10-04. 승인 근거: 대표의 시안 확인 후 「이대로 진행해」.
범위는 [승인 설계](superpowers/specs/2026-10-04-account-reports-pdf-design.md)이며 운영 배포·광고주 발송·광고 변경은 하지 않았다.

## 구현

- 실관리 단계의 확정 연결 계정을 검색·페이지 조회한다. 보고서 미생성 계정도 목록에 남기며 주간/월간·기간·업체/계정 번호로 찾는다.
- 계정별 고정 저장 판을 기본으로 열고 업체 합산을 선택한다. 이전 판의 담당 범위·비교 원천·일별 자료를 보존한다.
- 광고비/전환매출/ROAS/CPA, 보조 지표, 일별 차트, 전주·전월 비교와 숫자 기반 세 줄 요약을 제공한다. 자료 부족/계정 범위 변경/분모 0은 비교 불가로 구분한다.
- 관리 기록·계획 원천은 미연결 상태를 명시했다. 담당자 편집·AI 브리핑·실제 업무 기록 쓰기·공개 링크·발송은 이번 범위가 아니다.
- 다운로드 직전 담당 권한과 동일 판을 다시 확인한다. 화면 이탈·권한 변경·판 변경 중에는 파일 생성을 중단한다. 외부 변환 서비스 없이 브라우저 안에서 한글 A4 PDF를 만든다.
- 구형 보고서 숫자는 덮어쓰지 않는다. 정상 inventory writer의 보고서 단계가 원천이 있는 실관리 업체를 회당 20곳씩 새 판으로 생성한다. 원천 없는 구형 판은 보존하며 UI/GET만으로 재구성하지 않는다.

## 확인한 결과

- 관련 Python 98개 통과(보고서 생성·정정·API 권한·검색·목록·캐시·화면 자산·PDF/화면 Node 래퍼 포함).
- PDF Node 10개, UI 16개 assertion 및 비동기 경계 11개 테스트 통과. 한글 합성 글리프 실제 윤곽, 변조 글꼴 거절, HTTP 환경 SHA 검증, 화면 금액 단위 일치를 확인했다.
- 로컬 합성 업체만으로 Chrome에서 계정/업체합산/주간/월간, 검색, 미생성 계정, 부분 집계, 담당 직원 필터, 탭 재진입, PDF 내려받기를 확인했다.
- 320px에서 목록·상세에 문서 가로 넘침 없음. 부분 집계 전환 값은 0이 아니라 —로 표시된다.
- 실제 다운로드 월간 PDF 4쪽(762,331B)의 한글·검색 가능 텍스트·페이지 번호·숫자·일별 표를 검수했다. 이는 합성 자료 검증이지 운영 광고주 검증이 아니다.
- macOS 전체 엔진 시험은 기존 SQLite WAL 설정에서 잠금 대기로 중단되었다. 잠금 보호를 완화하지 않았으며 Linux 개발 CI의 전체 회귀 결과는 별도로 기록한다.

## 배포 준비에서 남은 항목

- 운영은 변경하지 않았다. 봉인·수신·코드 업그레이드 도구가 구 승인 커밋 `0a30285` 및 옛 경로 목록에 고정되어 있어 다음 승인 배포 시 정확한 커밋/파일 목록 갱신이 필요하다.
- 한글 글꼴은 원본 바이트·SHA를 유지한 gzip 자산으로 바꿔 파일별 1MiB 제한을 충족했다. 브라우저에서 직접 해제하므로 HTTP Content-Encoding을 붙이지 않는다.
- 전체 소스 묶음의 base64만 약 2.74MB로 기존 2MiB 봉인 한도를 넘는다. 한도·수신 정책을 임의로 변경하지 않았다. 배포 전에 별도 자산 포장 또는 검증된 전송 한도 조정을 결정·검증해야 한다.
- 새 라이브러리/글꼴 출처·라이선스·SHA는 `backend/naver_page/vendor/report-pdf/manifest.json`에 고정했다. 공개 취약점 검색 무발견은 보안 보증으로 표현하지 않는다.
