## 설계

고정 대기 시간을 늘리는 안은 안정됐지만 화면 밖에 있는 버튼을 해결하지 않는다. 가림 검사를 무시하거나 강제 합성 클릭하는 안은 채택하지 않는다. 같은 검증 대상의 실제 가시 영역과 제한된 스크롤 보정으로 해결한다.

1. 실제 Chrome에서 현재 코드의 화면 밖 실패를 만드는 CSS/viewport 조건을 먼저 재현한다. 사이트가 실제로 같은 조건이었다고 단정하지 않는다.
2. 버튼의 보이는 영역 안에서 입력 지점을 정하고, 같은 요소가 그 좌표의 최상위 대상인지 확인한다. 가림·숨김·다른 요소로 바뀜은 계속 거절한다.
3. 화면 밖이라면 실제 스크롤 가능한 범위에서 최대 2회만 위치를 보정하고 다시 안정·가시성 검사를 한다. 기존 검사 시간 한도와 마우스 이동 후 재확인을 유지한다. 문서 CSS·창 크기·배율을 바꾸지 않는다.
4. 추가 클릭은 하지 않는다. press/release 최대 1쌍, 불확실한 전달 후 합성 클릭 금지, 관측기 정리와 페이지/응답 검증을 유지한다.
5. 가로·세로 위치, 화면 크기, 보정 횟수는 제한된 숫자 진단으로만 기록한다. 기존 500자 JSON 한도와 개인정보 제외를 회귀 검사한다.

- 압축 파일의 8개 런타임 파일과 검증 소스를 대조한다. 먼저 2번 한 대에서 실제 2페이지·서버 기록·순위 대조가 필요하다.

실제 Windows·사이트 검증 전 후보이며, 로컬 시험 성공을 현장 성공이나 차단 해제로 표현하지 않는다.

## 구현 결과

`pagerLocate`의 guarded 경로만 보완했다. 자연스러운 스크롤 이후 안정된 요소의 화면 교집합이 4×4 CSS px 이상이면 그 안쪽의 정수 중심점을 다시 hit-test한다. 그렇지 않으면 root window의 필요한 축만 `scrollBy(..., behavior:'instant')`로 이동하고 다시 안정화한다. 보정 횟수는 start/check/hover 전체를 통틀어 최대 2회이며, 기존 1.5초 페이지 검사·2.2초 worker 응답 대기·최대 3회 이동 후 재검사 제한을 늘리지 않았다.

중첩 스크롤 부모를 찾아 강제 이동하지 않는다. 고정 요소·가림막·작은 가시 영역 등으로 검사를 통과하지 못하면 클릭 없이 멈춘다. 전체 중심이 화면 밖인 큰 버튼이라도 실제 보이는 영역이 있고 같은 요소가 최상위일 때만 클릭할 수 있다.

독립 리뷰 중 투명한 복제 버튼이 교집합 hit-test에 잡히는 회귀를 발견했다. 본인/조상의 opacity=0, display:none, content-visibility:hidden과 본인의 계산된 visibility:hidden/collapse를 최초 선택 및 연속 검사에서 거절하도록 보완했다. 조상의 visibility를 자식이 visible로 재정의한 실제 가시 요소는 허용한다. 페이지 CSS 자체는 변경하지 않는다.

원래 대상 판별 규칙·기존 합성 fallback 조건·응답/페이지/검색어 검증·부분 보존·차단 휴식·작업 배분·미전송함은 유지했다. 운영 서버와 노트북은 조작하지 않았다.

## 진단 해석

기존 자동 TAP_PROBE의 `click.geo`에 제한된 문자열을 추가한다. 예: `I1:325,360,1200,720`.

- 첫 글자(들): 버튼 **전체 사각형의 중심** 방향. I=화면 안, L/R/T/B=좌/우/위/아래, 조합 LT/LB/RT/RB 가능.
- 이어지는 0~2: 누적 보정 시도 횟수. 뒤 숫자는 전체 중심 x,y와 viewport 너비,높이(CSS px)다. 반올림·최대 절댓값 9999로 제한한다.
- 교집합에서 선택한 실제 클릭점과 전체 중심은 다를 수 있다. 일부 보이는 큰 버튼의 `B0`도 안전한 클릭일 수 있으며 I라고 성공을 뜻하지도 않는다. `guard`, 이벤트, 페이지/응답 증거와 함께 읽는다.
- `none`은 관측 값이 없거나 형식이 맞지 않는 경우다. 좌표는 마지막 표본 값이며, 이전 키워드 값을 재사용하지 않는다.
- 새 필드에 DOM 원문·검색어·상품·오류 문자열은 넣지 않는다. 기존 별도 keyword/href 필드까지 익명화했다는 뜻은 아니다.
- 허용값 최대 길이·nullable 조합의 자동 진단은 483자였고, 500자 이내 유효 JSON 검사를 통과했다. 수동 HUMAN 진단에는 이전 자동 클릭 정보를 섞지 않는다.
