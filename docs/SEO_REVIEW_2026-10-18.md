# SEO 개선 사용·복구 안내

## 직원 사용 흐름

1. SEO 최적화에서 업체와 연결 상품을 선택한다. 연결 자료가 없으면 상품 URL과 확인한 사실만 직접 입력한다.
2. 대표 키워드를 확인하고 접힌 ‘상품 사실·현재값 확인 및 보완’에서 자동 채움 내용을 확인한다. 현재 태그·제목·메타를 모르겠으면 미확인으로 둔다.
3. ‘검수 추천 생성’을 누른다. 저장된 상품 자료만 참고하며 이 동작으로 네이버 추가 수집을 요청하지 않는다.
4. 자료 시점·확보 수·미확인 사항과 네 항목의 현재값·추천안·변경 이유를 읽는다. 태그/메타 추천을 경쟁사의 실제 설정값으로 해석하지 않는다.
5. 항목마다 채택·수정·보류를 선택한다. 보류는 현재값 유지이며 미확인은 미확인으로 보존된다.
6. 실제 상품 사실과 네 항목을 검토했다는 확인란을 선택하고 승인본을 저장한다. 저장된 승인본을 복사해 스마트스토어에서 직원이 직접 반영한다.
7. 승인본 저장·복사는 외부 반영 완료가 아니다. 실제 스토어 반영 여부는 직원이 확인한다. 저장 이력에서 당시 입력·추천·승인·기준·근거를 다시 확인할 수 있다.

## 근거 표시 읽는 법

- 20/20은 상품명 자료 확보 수이며 순위·상품 속성·그룹/카탈로그 검증 완료와 다르다.
- 현재 저장 스키마는 그룹상품·카탈로그 처리 근거가 부족하므로 이를 검증 완료로 올리지 않는다.
- 오래된 자료·부분 자료·출처 미확인·자료 없음·읽기 실패를 구분한다. 미확인을 0건 또는 실측값으로 치환하지 않는다.
- 공통어는 한 상품 안의 반복을 한 번으로 센다. 자주 등장하더라도 자기 상품과 무관하면 채택하지 않는다.
- 태그의 실제 네이버 등록 허용 여부는 미검증이다. 필요한 관련어만 사용하며 최대 10개를 억지로 채우지 않는다.

## 현재 운영 생성 장애

운영은 지원 종료된 `claude-sonnet-4-20250514`를 설정하고 있으며 보존 로그에 HTTP404 두 건이 확인됐다. 공식 종료일은 2026-06-15이다. 현재 코드의 기본값은 다른 모델이지만 운영 환경변수가 이를 덮고 있어 소스 기본값만 고쳐서는 복구되지 않는다.

보존 로그의 첫 SEO 실패는 2026-10-18 20:47:07 KST, 마지막은 20:54:14이다. 로그 자체는 10/13부터만 남아 있다. 이 첫 실패를 실제 장애 시작일로 단정하지 않는다. 과거 ‘tokens’ 로그는 JSON 검증 전 공급자 응답 수신이라 업무 생성 성공도 확정할 수 없다.

복구에는 대표 승인 후 SEO 전용 지원 모델 설정과 제품 반영, 실제 생성 확인이 필요하다. 공용 채팅의 `CLAUDE_MODEL`을 일괄 변경하지 않는다. 새 `SEO_CLAUDE_MODEL`을 지정하지 않으면 공유 설정을 그대로 사용하며, 종료 모델일 때는 추가 호출 없이 구체적인 오류를 안내한다.

## 검증 범위와 변경 범위

- 임시 DB/공급자 모형 API, 캐시 근거, 운영과 같은 React18.2.0 실제 DOM, 기존 배포 게이트, 실제 번들을 확인했다.
- 기존 공용 진단 API·전산 소비·수집기·순위 기록·계약 동기화는 수정하지 않았다.
- 운영 DB/업체 기록 변경·모델 환경 변경·재시작·제품 배포·네이버 상품 수정은 하지 않았다.
- 생성/검수는 `seo_generate.py`·`seo_review.py`, 근거는 `seo_evidence.py`, 개정 기준은 `seo_policy.py`에 모았다. 기존 테이블을 삭제하거나 완료 업무를 초기화하지 않는다.
