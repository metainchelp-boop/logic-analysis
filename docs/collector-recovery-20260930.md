# 중앙 배정 휴식·재개 수정 — 1.28.1-rc1

## 현재 상태와 승인 범위

- 기준: 이전 후보 `b2e963f` / 확장 1.28.0-rc1. 운영 기준 main `60864fb` / 확장 1.27.0과 구분합니다.
- 사용자 승인: 차단 휴식이 해제되는 문제와 임시 대기 후 재개가 늦어지는 문제를 수정하고 버전을 갱신합니다.
- 이번 증분의 실행 코드 변경은 확장에 한정합니다. 관련 배선 시험을 갱신하고 기존 배포 전 검사에 새 회귀 시험을 추가했습니다(배포 실행·트리거 변경 없음). 이전 후보의 2페이지 판독·이동 및 서버 관측 검증 수정은 유지합니다.
- 운영 배포, 서버 설정·DB 변경, 중앙 배정 활성화, Windows 확장 교체는 하지 않았습니다. `release_ready: false`입니다.

## 변경 내용

1. 중앙 배정에서 앞 키워드가 성공했어도 같은 회차에서 뒤에 차단을 만나면 새 휴식을 지우지 않습니다. 6시간 기본 휴식과 24시간 감속 창은 유지합니다.
2. 중앙 배정의 `WAIT_BUDGET`, `IDLE`, 일시 오류를 `finishedHour`로 기록하지 않습니다. 기존 버전이 남긴 같은 시간대 완료 표식도 중앙 배정을 막지 않습니다. 종전 시간대 경로와 중앙 비활성 폴백은 기존 완료 표식을 계속 존중합니다.
3. 서버 `claim.nextAllowedAt`(epoch 초)을 로컬 저장소에 보존합니다. 허용 시각 전에는 재등록·배정을 하지 않으며, 시각 이후 첫 daily 알람에서 다시 등록·배정합니다. 서비스 워커가 다시 시작돼도 유지됩니다. 대기 종료 자체가 작업 허가는 아니며 새 `claim`이 필요합니다.
4. 회차 시간 예산을 실제 소진한 경우 시작 시간대의 다음 정각까지 대기합니다. 작업이 정각을 넘어 끝나도 추가로 한 시간을 미루지 않습니다. 임시 대기 수정 때문에 시간 예산을 즉시 새로 받아 계속 도는 것을 막습니다.
5. 없거나 잘못된 서버 시각은 날짜 변환 예외를 만들지 않습니다. 다음 1분 알람에서 재확인하며 같은 회차에서 반복 요청하지 않습니다. 재개 시 만료된 대기 표시는 비웁니다.
6. `IDLE` 로그를 '오늘 몫 없음'에서 '현재 배정 가능한 몫 없음, 다음 알람에서 재확인'으로 정정했습니다.

## 검증 결과

먼저 수정 전 실제 코드로 휴식 취소 및 시간대 완료 오기록 실패를 재현하고, 각 수정 후 통과를 확인했습니다. 시간 예산·잘못된 시각도 별도 실패 재현 후 수정했습니다.

- 새 `coordinated_recovery.test.js`: 전체 background 서비스 워커를 VM에 올려 실제 daily 알람, 수집, 업로드, 휴식 설정·해제, 재시작을 검증합니다. Chrome/HTTP/페이지 실행/시간만 가짜 경계입니다. 실제 사이트의 차단율을 검증한 시험은 아닙니다.
- 신규 9개 시나리오: 성공→차단→재시작(중앙·온디맨드 자동 경로), 시간 예산, 같은 시간 내 대기 재개, 잘못된 시각, 구버전 완료 표식/종전 폴백, IDLE·통신 오류, 수동 실행과 정지, 정상 회복과 감속 유지, 정각 넘김.
- 확장 `.test.js` 17개 파일 전체 통과. Node 집계 27개 시험 단위 통과(기존 파일 내부 자체 assertion 숫자와 다릅니다).
- 서버 `test_collector_coord.py` 40개 검사 통과. 최소 SQLite fixture에 `collected_serp`가 없다는 기존 경고는 있으나 실패는 없습니다.
- 이전 2페이지 후보와 관련된 서버 시험 9개 파일도 재실행해 통과했습니다. 이 중 기존 배선 시험 1개는 함수 호출 결과를 변수에 저장한 새 구조를 반영해 수정했습니다. 실제 분기 동작은 신규 VM 시험에서도 검증합니다.
- 실제 Chrome 격리 페이지 시험 5개 통과: 지연 응답, 캐시 라우터, HTTP418, 가려진 버튼, 다음 그룹. 정상은 1~80위·페이지 클릭 1회, 제한 상황은 확인한 첫 40위만 보존. 모든 HTTP 요청은 로컬에서 가로채며 실제 네이버 요청은 없습니다.

재현 명령:

```sh
TZ=Asia/Seoul node --test collector-extension/tests/*.test.js
PYTHONDONTWRITEBYTECODE=1 python3 backend/tests/test_collector_coord.py
COLLECTOR_TEST_CHANNEL=chrome node collector-extension/tests/pagination_browser.test.cjs
```

브라우저 시험은 기존 Playwright 설치의 `NODE_PATH`가 필요할 수 있습니다. 신규 설치는 수행하지 않았습니다.

## 바꾸지 않은 것과 남은 현장 검증

- 수동 '지금 수집 실행'의 기존 로컬 차단 휴식 우회 동작은 유지했습니다. 새로 저장한 서버 대기는 수동 실행도 지킵니다. 차단 중 강제 실행은 권하지 않습니다.
- 중앙 배정 대기는 중앙 경로에 적용됩니다. 온디맨드는 기존 별도 예산·경로입니다. 전체 경로를 하나의 예산으로 통합한 변경이 아니므로 통합 예산·인증 만료·미전송 처리의 운영 검증이 추가로 필요합니다.
- 알람 지연, 컴퓨터 절전·꺼짐, 실제 네이버 정책 때문에 정확히 지정 초에 재개하거나 오전 10시까지 전량 수집한다고 보장하지 않습니다. 깨 있고 알람이 정상인 경우 허용 시각 이후 다음 1분 알람에 재확인합니다.
- 중앙 배정이 실제로 꺼져 있는 노트북은 이번 두 수정의 중앙 경로를 사용하지 않습니다. 활성 여부를 확인해야 하며, 시험을 위해 임의로 켜지 않습니다.
- 이전 2페이지 개선의 서버 변경은 별도 검토·배포가 필요합니다. 확장 ZIP 교체만으로 서버 변경까지 적용되지 않습니다.
- 승인 후 한 Windows 노트북에서 기존 확장 ID·로컬 저장소·미전송함을 유지하며 제한된 키워드로 확인합니다. 확장을 제거/재설치하거나 쿠키를 지우지 않습니다. 확장 새로고침 뒤 해당 수집기 작업 탭을 새로고침해 새 캡처 코드를 로드합니다.
- 현장 합격: 성공 뒤 차단 시 휴식 유지, 휴식 동안 새 쇼핑 이동 없음, 짧은 서버 대기 뒤 같은 시간 재배정, 재시작 후 대기 유지, 2페이지 실제 수동 순위와 저장 순위 대조. 차단을 일부러 유발하지 않으며 실제 제한이 나타나면 시험을 멈춥니다.
- 실제 두 노트북의 수집량·실패율·오전 10시 마감 실적은 아직 확인하지 않았습니다.
