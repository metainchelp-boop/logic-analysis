# 출근 전 수집·정정·전체폭 화면 실행 계획

기준 `26fd776`, 대표 통합 배포 승인 2026-10-03. 관련 설계는 `../specs/2026-10-03-morning-collection-report-revisions-design.md`.

## 작업과 검증

1. 수집 담당: 고정 기간·세대 재조회, 집계 대기 별도 지연, 날짜 이월, 과거 원천 역행 차단, 예산 안의 공정 처리, 자정 목록·아침 간섭 수정. 공개 경계의 합성 시계/네이버 응답 시험 → Linux 실제 Store/Writer 검증.
2. 보고서 담당: 숫자 판과 재검증 상태 분리, 날짜 기반 dirty 기간, 한 업체 영향기간 원자 갱신, 이전 판/차이·승인 보호. 순수 집계/경계 시험 → 실제 SQLite 원자성·귀속 시험.
3. 화면 담당: 6탭 전체폭·항목명 있는 좁은 화면 카드, 시간/집계 대기, 보고서 이력·기간 재조회. DOM 행동 시험 → Linux 브라우저 전 폭/내부 넘침 검사 → 실제 운영 브라우저 확인.
4. 통합 담당: 추가형 schema11 이관, 인증된 API/단일 writer 경계·필드 제한, 회귀 및 별도 검토, 배포 제어 schema10→11 사본/복구 보호. 기존 자격·전산·다른 앱 불변.
5. 최종 앱 커밋 고정 → 전체 Linux CI 성공 → 실행 소스·압축·Store 지문 봉인 → 운영 준비 및 원본 사본 검증 → 전용 엔진·릴레이 1회 배포 → 독립 상태/수집 진도/실제 화면 확인. 실패판은 배포하지 않음.

## 고정점

- Store 공유 파일은 수집 메서드 구간과 보고서 구간을 나누어 최소 패치한다. schema·이관은 통합 담당만 수정한다.
- 원천 실패/누락≠0, 합계 증가만 인정하는 조건 금지, 옛 승인 새 판 승계 금지, 현재/과거 귀속 및 담당자 범위 보존.
- Mac 임시 DB 잠금 오류를 회피하도록 제품 잠금을 바꾸지 않는다. 로컬 순수 시험과 Linux 실제 통합 결과를 구분한다.
- 관련 없는 `outputs/`·사용자 변경 보존. 광고 집행·입찰·외부 발송·유료 호출은 하지 않는다.
- 신규 예약 정책은 제품 코드로 구현한다. 별도 Codex 예약 작업을 만들지 않는다.
