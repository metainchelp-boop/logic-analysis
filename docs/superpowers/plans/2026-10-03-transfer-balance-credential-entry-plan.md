# 이관 잔액·검색·계정 입력 구현 및 배포 계획

2026-10-03 대표 `응 구현하고 배포해` 승인. 기준 AD f430f51, 제품 e132a4b. 설계 문서 `../specs/2026-10-03-transfer-balance-credential-entry-design.md`를 따른다.

1. 현 상태·공유 소식판·운영 소스와 전산 최신 소스를 확인한다. 관련 없는 변경·출력·기존 운영 데이터를 보존한다.
2. 독립 작업 A: 관제 화면에서 잔액순·현재 목록 합계·누락 대조 검색·전산 입력 링크를 동작별 실패 시험→최소 구현→통과 순으로 진행한다.
3. 독립 작업 B: 전산 최신 기준에서 기존 열쇠 팝업 직행·네이버 카드 프리셋·실패/닫기/지연 응답을 같은 방식으로 검증하고 구현한다. 변경 필드만 보내는 저장 경로를 유지한다.
4. 합성 자료로 승인된 권한·0/미확인·소수 합산·검색 독립·새 창·잘못된 업체·로그인·비밀정보 보존을 검사한다. 기존 회귀·타입검사·빌드와 독립 코드 검토를 수행한다.
5. 실제 브라우저의 로컬 확인 화면에서 PC/모바일 배치와 사용자 동작을 검증한다. 운영 업체에 시험 값을 저장하지 않는다.
6. 전산 FE 변경만 PR로 검증·배포한다. 보호 승인·충돌·범위 밖 변경 발견 시 중단하고 알린다. 실제 직행 화면이 열린 뒤 관제 전용 배포를 수행한다.
7. 관제 배포는 검증한 소스만 봉인하고 기존 안전 제어의 준비→적용→독립 상태 확인 절차를 따른다. 스키마·전산/네이버 업무 원본·기존 앱·nginx·비밀값은 변경하지 않는다.
8. 운영 화면에서 정렬·합계·검색·팝업 진입을 읽기/취소로 확인하고 결과와 남은 실번호 저장 검증 범위를 보고한다. 공유 소식판·지식 기록을 갱신한다.

예상 45~70분. 설치된 writing-plans 스킬이 없어 이 계획 문서로 대체한다. 단위 동작별 검증과 마지막 통합 회귀를 구분한다.
