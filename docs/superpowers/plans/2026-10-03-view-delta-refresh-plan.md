# 관제 변경분 갱신 구현 계획

기준 `ac18566`. 대표가 2026-10-03 “진행해”로 설계 문서 검토를 승인했다. 구현·합성 검증·확인 화면 제공 범위이며 운영 배포와 재시작은 제외한다.

1. 서버: 기존 네 GET의 선택적 변경분 응답, 동일 읽기 스냅숏과 현재 권한 검증, 크기·개수·수명 제한 캐시. 검증: 원래 GET 호환, 추가/정정/제외 후 전체 응답 동등성, 다른 사용자/세션/범위/날짜/만료 커서 격리.
2. 화면: 네 탭의 메모리 재사용과 변경분 병합, 권한 오류 제거, 목록 DOM 보존, 확인 시각·실패 표시. 검증: 변경 없는 행과 초점/검색 유지, 지연 응답 차단, 오류/로그아웃/자정/보고서 페이지 소멸 복구.
3. 통합: 실제 엔진+중계+브라우저 합성시험, 변경 전후 바이트 측정, 기존 회귀시험. 독립 검토의 설계 준수·보안·표준 지적을 수정한다.
4. 인계: 실제 제품 코드로 합성 자료만 사용하는 로컬 확인 화면과 캡처 제공. 변경 파일만 커밋·작업 브랜치 푸시. 운영 반영 전 상태를 명시한다.

## 서버·화면 계약

- 기존 경로의 query `view_sync=1`을 지정하면 변경분 프로토콜을 사용한다. 다음 조회에는 선택적으로 `view_cursor`를 보낸다. 두 값은 네 허용 GET의 공통 처리에서만 해석하며 기존 handler에는 넘기지 않는다.
- 응답: `{version: 1, mode: 'full'|'delta'|'unchanged', cursor: string|null, base_cursor: string|null, checked_at: ISO, data: object|null, rows: object|null}`.
- `full`: `data`는 기존 전체 응답, `rows=null`, `base_cursor=null`. 커서 소실/무효/만료/권한 지문 변화 시 이것으로 복귀한다.
- `unchanged`: 이전 응답과 동일. `data=null`, `rows=null`. 화면은 확인 시각만 갱신한다.
- `delta`: `data`는 현재 요약/권한/상태 등 원본의 `rows` 이외 전체 필드, `rows={key_fields, upsert, removed, order}`. 대시보드는 목록이 없으므로 현재 집계 전체가 `data`, `rows=null`이다.
- 행 키: `/accounts`는 `ad_account_no`, `/board`는 `possibility_id`, `/reports`는 `possibility_id, period_key`. 키 문자열은 해당 필드 값 배열의 JSON이다. null/중복/안전하지 않은 숫자는 `full`로 복귀한다. 내부 고객 번호를 새로 노출하지 않는다.
- `removed`는 이번 조회 목록에서 제외된 키, `order`는 현재 서버 정렬 키 전부다. 금액과 개정 값은 행 전체 교체이며 가산하지 않는다.
- 클라이언트는 응답 기준 커서·구조·키·정렬의 완결을 먼저 검사하고 일괄 반영한다. 잘못된 변경분은 캐시를 버리고 커서 없는 요청을 한 번만 재시도한다.
- 구버전의 정상 전체 JSON 응답은 전체 교체로 호환한다. 변경분 파라미터를 거절하는 구버전 서버는 일반 GET으로 한 번 복귀한다. 인증/권한 오류는 호환 재시도로 우회하지 않는다.
