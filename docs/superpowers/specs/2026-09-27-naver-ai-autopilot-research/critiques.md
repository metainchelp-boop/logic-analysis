

######## api — 설계안이 내세운 네이버 검색광고 API 주장을 로컬 명세(sa-pages/assets/json), 공지 226개, searchad-apidoc 과 하나씩 대조했다. 대부분은 명세와 맞고, 모르는 부분도 정직하게 「미확인」으로 적었다. 명세와 맞는 주요 주장은 다음과 같다.
- 소재 수정 fields 허용값이 userLock·inspect 뿐이라는 점. adAttr 태그(#hidden-create #hidden-response #required-update) 원문도 일치한다.
- 그룹 bidAmt 범위 70~100,000 과 fields=bidAmt.
- autobidStrategy 는 쇼핑몰 상품형 전용이고 값이 고정이라는 점.
- 쇼핑몰 상품형은 요일·시간 가중치를 지원하지 않는다는 점.
- criterion/{type} 로 교체하면 빠진 코드가 전부 해제된다는 점, SHOPPING_EXTRA 는 API 로 생성할 수 없다는 점.
- adRollingType 은 WEB_SITE·POWER_CONTENTS 에서만 유효하다는 점.
- hh24 는 과거 7일까지, ids 에 캠페인 유형을 섞으면 11003.
- stats 지연 2시간, 대량 보고서 보관 14일·CHANGED 상태, avgRnk 는 파워링크 전용, NPLA 예상가는 한 번에 200개.
- aiAdsOptIn 을 안 적으면 true, useAdvoost 켜면 3755.
- 매니저 API 는 GET 4개(조회 전용)이고 accountRole 은 MASTER/READ_ONLY. 매니저 라이선스로 하위 계정에 쓰기가 되는지는 「미확인·실증 필요」로 둔 것도 옳다. 매니저 권한을 크게 과장한 곳은 없다.

그러나 고쳐야 할 오류와 빠진 근거가 있다.
1. 명세에 적힌 「현재 소재 입찰가 읽는 길」을 놓쳤다. ShoppingProduct·CatalogAd 마스터 보고서에 Bid 와 Using Ad Group Bid Amount 칸이 있고, 실제 GET 응답 예시에도 adAttr 가 나온다. 이것을 놓쳐 「현재가를 모르면 1차는 그룹가만」이라는 후퇴안을 과하게 잡았다.
2. 쇼핑용 마스터 보고서 항목을 잘못 골랐다. Ad 는 파워링크 단일 소재 마스터, Qi 는 파워링크 키워드 품질지수(4 고정)이다. 쇼핑은 ShoppingProduct·CatalogAd·AdQi 를 써야 한다.
3. 호출 한도 공지를 잘못 읽었다. 5분 휴지 지침은 키워드도구 한정이고, 그 공지에는 1016 도 없다. 같은 공지가 적은 「대용량·마스터 보고서는 호출 속도 제한이 상대적으로 느리다」는 800곳 계획에 반영하지 않았다.
4. 「쇼핑은 순위 지표가 없다」는 틀렸다. 쇼핑 검색어 보고서에 Sum of AD rank 칸이 있다.
5. 「수정은 48시간 안」을 전제로 D-2 까지만 다시 받는다. 공지에는 13일 뒤 복구된 사례가 있어 이 전제가 틀렸다.
6. 공유예산 제한 상태값을 빠뜨렸다.
7. 쇼핑 소재 PUT 에 adAttr 가 필수라는 점(#required-update)을 고려하지 않았다.

치명적인 거짓 주장은 없다. 다만 1·2·3 은 1차 쇼핑의 쓰기 검증과 800곳 호출 설계에 직접 영향을 주므로 착수 전에 고쳐야 한다.
