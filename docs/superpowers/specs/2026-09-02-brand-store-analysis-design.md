# 신고 #246 브랜드스토어 상품 로직분석 지원 설계

## 1. 목표

일반 스마트스토어에서 사용하던 흐름을 바꾸지 않으면서 네이버 브랜드스토어 상품에서도 다음 전 과정을 동일하게 제공한다.

1. 상품 페이지 자동 인식
2. 우측 분석 패널 표시
3. 자동 스크롤과 HTML 수집
4. 로직분석 탭 전송
5. 상품명·가격·카테고리·리뷰수·평점·스토어 정보 분석
6. 상품·스토어 매칭과 네이버 스토어 관련 점수 판정

신고 재현 주소는 `https://brand.naver.com/vayapet/products/9864738770`이다.

## 2. 확인된 원인

- 확장 권한과 content script 실행 대상이 `smartstore.naver.com`으로 한정돼 있다.
- 팝업의 상품 페이지 판정 정규식도 스마트스토어만 허용한다.
- 브랜드스토어 초기 상태는 `__NEXT_DATA__`가 아니라 `window.__PRELOADED_STATE__.simpleProductForDetailPage`에 가격·카테고리 등을 둔다.
- 일부 후속 상품 매칭·신뢰도·네이버페이 판정이 스마트스토어 호스트만 네이버 스토어로 인정한다.

따라서 도메인 한 줄만 추가하면 진입은 되더라도 분석 결과 일부가 계속 누락된다.

## 3. 검토한 접근

### A. 확장 진입만 허용

manifest와 팝업만 수정한다. 변경은 가장 작지만 가격·카테고리 누락과 점수 불일치가 남으므로 실사용 정상화 기준을 충족하지 못한다.

### B. 전 경로의 필요한 분기만 공용화 — 채택

확장 진입, 브랜드 상태 파싱, 상품·스토어 폴백, 네이버 스토어 판정을 하나의 지원 범위로 묶되 이번 결함과 직접 관련된 코드만 수정한다. 기존 스마트스토어 흐름과 HTML 직접 입력·북마클릿 폴백은 그대로 유지한다.

### C. 판매 플랫폼 전체 추상화

스마트스토어·브랜드스토어·가격비교 등을 범용 어댑터 구조로 전면 개편한다. 장기 확장성은 있으나 이번 신고에 비해 변경 범위와 회귀 위험이 커서 제외한다.

## 4. 구현 설계

### 4.1 확장프로그램

- `brand.naver.com`과 `m.brand.naver.com`을 host permission과 상품 content script 대상에 추가한다.
- 팝업은 스마트스토어와 브랜드스토어의 `/products/{숫자}` 경로만 허용한다.
- 표시 문구를 특정 채널에 종속되지 않은 `네이버 스토어 상품`으로 바꾼다.
- 팝업의 하드코딩된 버전 표기를 제거하고 manifest 버전을 읽어 표시한다.
- 확장 버전을 올리고 설치 안내에 기존 폴더 교체·확장 새로고침 절차를 기록한다.

### 4.2 상세정보 파싱

- 기존 `__NEXT_DATA__` 파싱을 우선 유지한다.
- 값이 없을 때 브랜드스토어의 `simpleProductForDetailPage`를 안전하게 읽는 폴백을 추가한다.
- `eval`은 사용하지 않는다. script에서 필요한 객체 구간을 추출하고 JavaScript 리터럴의 `undefined` 같은 비 JSON 값을 안전하게 정규화한 뒤 파싱한다.
- 가격·카테고리뿐 아니라 상품 ID·리뷰수·평점도 같은 표본으로 검증하되, 기존 추출값이 있으면 덮어쓰지 않는다.

### 4.3 매칭과 점수

- 네이버 스토어 호스트 판정을 한 곳에 모아 `smartstore.naver.com`과 `brand.naver.com`을 동일 범주로 처리한다.
- 상품 ID가 있는 기존 정확 매칭을 우선하고, 스토어명 폴백은 그 다음 순위를 유지한다.
- 브랜드스토어라는 이유만으로 신뢰도·네이버페이 관련 점수가 낮아지지 않도록 호스트 판정을 공용화한다.
- 순위 수집기(`collector-extension`)와 가게 연결 규칙(`rank_link`)은 별도 기능이므로 수정하지 않는다.

## 5. 오류 처리와 무회귀

- 브랜드 데이터가 없거나 구조가 바뀌면 기존 파서와 화면을 실패시키지 않고 해당 필드만 미확인으로 둔다.
- HTML 30KB 미만 전송 차단, 10분 만료, SSO, 북마클릿·직접 입력 폴백은 그대로 유지한다.
- 일반 스마트스토어와 비상품 페이지의 기존 판정을 회귀 테스트로 고정한다.
- URL 호스트를 무작정 넓히지 않고 네이버 스토어의 정확한 호스트와 상품 경로만 허용한다.

## 6. 검증 기준

자동 검증:

- 실제 manifest와 popup 코드에서 스마트스토어·브랜드스토어는 활성, 비상품 URL은 비활성
- 브랜드 상품 표본에서 가격 `12,300`, 리뷰 `540`, 평점 `4.88`, 카테고리 존재
- 기존 스마트스토어 분석 회귀 테스트 통과
- 상품 매칭·네이버 스토어 점수 판정에서 두 호스트가 같은 정책 적용
- 프론트 번들 빌드 및 백엔드 회귀 테스트 통과

브라우저 검증:

- 신고 주소에서 FAB가 정확히 1개 표시
- 팝업이 상품 페이지로 인식
- 키워드 입력 후 수집·전송 성공
- 로직분석 탭에서 자동 분석 시작
- 상품명·가격·카테고리·리뷰수·평점이 모두 표시

## 7. 배포 경계

- 백엔드·프론트 변경은 운영자 배포 지시 후 `main` 배포로 반영한다.
- `extension/**`는 서버 배포에서 제외돼 있으므로 별도 ZIP을 만들고 직원 PC의 기존 확장 폴더를 교체한 뒤 확장 관리 화면에서 새로고침해야 한다.
- 서버 배포 성공만으로 신고 완료 처리하지 않는다. 직원 PC 확장 교체와 신고 주소 E2E까지 확인한 뒤 완료로 판정한다.
