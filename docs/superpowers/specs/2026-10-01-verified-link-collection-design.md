# 검증된 계정 연결과 즉시 조회

## 승인과 범위

대표님이 2026-10-01 승인한 범위는 검증된 광고주 계정의 연결 확정과 즉시 데이터 조회입니다. 광고 변경, 자동입찰, 알림, 공유 성과 전송, 직원 권한 확대, 계약 변경은 포함하지 않습니다. 읽기 검증판 전체를 해제하지 않습니다.

## 설계

- 기존 제한판과 별개인 좁은 기능 표지를 두어 대표 권한에서 연결 확정 및 조회 요청/상태만 열고 나머지 경로는 종전처럼 차단합니다. 기본값은 닫힘입니다.
- 기존 불투명 연결 참조와 최신 권한·조직·계정·계약 범위 검사를 재사용합니다. 자동 짝 또는 번호는 일치하나 이름이 다른 단일 계정만 확인할 수 있으며 다른 광고주 주장/중복·충돌·이름만 비슷한 후보는 일괄 확정하지 않습니다. 실제 저장 직전에 같은 검사를 다시 수행합니다.
- 조회 요청은 감사를 남기고 단일 대기 슬롯에 넣습니다. 기존 예약 처리기의 잠금과 단일 DB 작성자를 사용하며 별도 쓰기 연결이나 임의 시각, 초기 설치 요청 재사용은 금지합니다.
- 현재 전산/계정 자료로 재검증한 후 실제 시각으로 GET 전용 수집기를 실행합니다. 최대 600초, 하루 3회, 20분 재시도 제한을 보존합니다. 요청자 권한이 사라지거나 신선도/범위 확인이 실패하면 진행하지 않습니다.
- 처리 상태와 실제 성공/실패 수를 화면에서 확인합니다. 요청 접수와 수집 완료를 구분하고 실패를 0원·정상으로 표시하지 않습니다.
- 서비스 재시작 시 대기 요청은 재실행하지 않습니다. 감사 이력과 기존 수집 기록은 보존합니다.

## 구현·검증 순서

1. 닫힌 경로·대표 한정·최신 참조·중복/기한/권한 회수 동작의 회귀 테스트를 추가하고 작은 단위로 구현합니다.
2. 단일 수집 요청과 예약 처리기를 연결하고 실제 네트워크 경계에 시간제한을 적용합니다.
3. 버튼·실행 상태를 기존 화면에 추가하고 API 및 브라우저 합성 검증을 실행합니다.
4. Linux 전체 검증과 고정 소스 지문을 확인하고 기존 설정·스키마·초기 설치 자료를 보존하는 코드 전용 배포를 수행합니다.
5. 운영 화면에서 정확히 검증된 연결을 확정한 다음 GET 조회를 요청하고 네이버 응답·저장 수·화면 표시를 대조합니다. 불명확한 계정은 보류 사유와 함께 남깁니다.

## 성공 기준

코드 검사나 계정번호 저장만으로 완료라고 하지 않습니다. 실제 대상이 있는 수집 회차와 그 결과의 관제 표시까지 확인합니다. 외부 권한 오류 등 남은 항목은 별도로 집계합니다. 기존 직원 가시 범위와 금지된 모든 쓰기/전송 경로의 차단을 회귀 검증합니다.
