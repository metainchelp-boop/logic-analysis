## 사용자가 보게 될 동작

| 상황 | 기대 동작 |
|---|---|
| 처음 접속·브라우저 새로고침 | 현재 권한에 맞는 전체 자료를 한 번 받는다. 네이버 수집을 새로 시작하지 않는다. |
| 같은 로그인 창에서 탭 재방문 | 서버의 현재 권한 확인 후 기존 화면을 재사용하고 변경분을 반영한다. |
| 같은 화면에서 목록 새로고침 | 화면·검색어·정렬·스크롤을 유지하고 ‘변경 확인 중’을 표시한다. |
| 계정 추가·실적 수정 | 새 행은 추가하고 같은 행은 최신 값으로 교체한다. 금액을 중복 합산하지 않는다. |
| 이관 해제·담당 변경·목록 조건 이탈 | 현재 목록에 해당하지 않는 행을 제거하고 요약 카드도 다시 맞춘다. 운영 원본을 삭제하는 기능은 아니다. |
| 일시적 통신 오류 | 권한 검증 상태에 따라 이전 자료를 유지하거나 가린다. 이전 자료 유지 시 마지막 확인 시각과 최신화 실패를 명시한다. |
| 권한 확인 실패·로그아웃·계정 전환 | 이전 업체 자료를 숨기고 캐시를 비운다. 다른 직원의 자료를 재사용하지 않는다. |

‘서버 변경 확인 시각’과 ‘네이버 자료 수집 시각’을 구분한다. 변경이 없다는 응답을 받아도 미수집 자료가 최신 자료로 바뀐 것처럼 표시하지 않는다.

## 선택한 방식과 대안

1. **선택: 서버 응답 차이 전송 + 창 안 메모리 재사용.** 기존 권한·판정 함수는 유지하고, 이미 조회한 응답과 현재 응답의 차이만 전송한다. 요청한 동작을 충족하면서 영구 저장소 변경을 피한다.
2. 화면만 유지하고 매번 전체 응답을 받는 방식은 단순하지만 반복 전송을 줄이지 못해 선택하지 않는다.
3. DB 변경 로그·구독 서버를 새로 만드는 방식은 더 큰 구조 변경이 필요하다. 이번 작업에 넣지 않는다.

## 구현 경계

### 서버

- 기존 `/accounts`, `/board`, `/dashboard`, `/reports` GET에서 선택적으로 변경분 조회를 제공한다. 기존 호출자는 기존 응답을 유지한다. 보고서는 기존 20건 페이지 단위를 유지한다.
- 모든 조회는 기존 인증·현재 조직·직원 범위·선택 범위 검사를 통과한다. 커서는 권한을 부여하는 수단이 아니다.
- 현재 응답은 기존 판정·집계 코드로 만든다. 권한과 데이터는 동일한 읽기 스냅숏에서 대조한다. 서버 DB 계산량 감소는 이번 개선의 보장 효과가 아니다.
- 읽기 트랜잭션은 토큰 검증 후 현재 조직을 읽기 전 시작하고 handler의 자료 생성이 끝나면 성공·실패 모두 종료한다. 캐시 잠금이나 네트워크 응답 전송까지 DB 트랜잭션을 유지하지 않는다.
- 서버 메모리의 이전 응답은 사용자·로그인 세대·권한 축소 여부·현재 조직과 권한 범위·조회 조건·자료 날짜·응답 형식 버전에 묶는다. 임의 커서·다른 사용자의 커서로 과거 응답을 얻을 수 없다.
- 서버 캐시는 개수·총 바이트·수명 상한을 모두 둔다. 재시작·축출·만료·범위 변경 때는 안전하게 전체 응답으로 복귀한다. 캐시 때문에 운영 DB 스키마나 수집 기록을 바꾸지 않는다.
- 목록 응답은 안정적인 행 식별자에 따라 추가/교체할 행, 제외할 식별자, 현재 순서, 최신 요약 정보를 보낸다. 카드·합계는 서버의 현재 값을 교체하며 클라이언트가 과거 합계에 더하지 않는다.
- 행 식별자는 유일하고 비어 있지 않은 경우만 사용한다. 광고 계정 번호가 없거나 중복된 행은 이름·번호 뒷자리로 추정하지 않고 전체 응답으로 복귀한다. 고객 내부 번호를 새로 공개해 식별자를 만들지 않는다. 별도 계정 연결 상세·확정 화면은 이번 변경분 조회 대상이 아니며 기존 최신 조회·쓰기 검증을 유지한다.
- 대시보드처럼 작은 집계 응답은 변경 여부 확인 후 집계 묶음을 교체한다. 무리하게 모든 숫자를 행으로 분할하지 않는다.
- `Cache-Control: no-store`는 유지한다. 브라우저 공용 캐시·CDN에 업체 자료를 남기지 않는다. 외부 API 호출, 수집 작업 등록, 연결 확정, 광고 쓰기는 하지 않는다.

### 화면

- 업체 자료는 현재 창의 메모리에만 보관한다. localStorage·sessionStorage·IndexedDB에 새 자료 캐시를 만들지 않는다. 기존 로그인 토큰 처리 방식은 유지한다.
- 보관 키에 사용자·조회 조건·날짜를 포함하고 캐시 크기를 제한한다. 범위 전환, 세션 종료, 날짜 변경 때 잘못된 이전 화면을 재사용하지 않는다.
- 숨겨진 탭의 자료는 서버가 현재 권한과 범위를 다시 확인하기 전 표시하지 않는다. 이미 보이는 같은 범위의 자료는 갱신 중임을 알리며 유지할 수 있다.
- 인증·접근 거절뿐 아니라 현재 조직 자료가 오래되어 권한을 확인할 수 없는 오류도 이전 자료를 즉시 숨기고 비운다. 일반 통신 오류와 이 권한 오류를 구분한다.
- 늦게 도착한 다른 탭·범위의 응답은 버린다. 중복 요청을 묶고, 현재 화면이 아닌 곳의 자동 갱신을 늘리지 않는다.
- 서버로부터 받은 변경분을 일괄 검증·적용한다. 기준 버전·행 식별자가 맞지 않으면 합치지 않고 전체 응답을 다시 받는다.
- 보고서 마지막 페이지가 사라진 경우 해당 페이지 재조회를 반복하지 않고 캐시를 비운 뒤 첫 페이지로 돌아간다. 보고서의 업체·기간이 같고 개정 번호만 바뀌면 이전 보고서를 최신 행으로 교체한다.
- 변경 없는 행은 다시 만들지 않아 검색·정렬·스크롤·키보드 초점을 보존한다. 제거된 행의 버튼이 남지 않게 한다. 쓰기 버튼의 실제 권한은 기존 서버에서 매번 재확인한다.

## 검증과 대표 확인 기준

1. 변경 없음: 최초 전체 응답 이후 전체 행 재전송·불필요한 행 재생성이 없는지 확인한다.
2. 추가·정정·제외: 새 계정, 금액 감소 정정, 이관 해제, 담당 변경, 필터 이탈을 합성 자료로 검증한다. 변경분 적용 결과가 같은 시점 전체 응답과 같아야 한다.
3. 권한: 다른 직원 커서, 퇴사, 범위 축소, 조직 자료 유효기간 경과, 로그아웃, 뒤로 가기에서 이전 업체 자료가 노출되지 않아야 한다.
4. 오류: 네트워크 실패, 요청 순서 역전, 자정·월초, 만료 커서, 서버 캐시 축출·재시작에서 누락·중복·이전 기간 혼합 없이 복구해야 한다.
5. 회귀: 계정 연결·수집 재시도·보고서 집계·기존 GET 응답·인증·읽기 전용 제한을 보존한다. 수집 요청과 광고 쓰기 호출은 0이어야 한다.
6. 실제 브라우저: 합성 자료로 탭 왕복, 필터, 새로고침, 오류 복구를 직접 확인하고 화면을 제공한다. 합성 화면에는 시험 자료임을 표시한다.
7. 측정: 동일 합성 데이터의 최초/변경 없음/일부 변경 응답 바이트와 행 변경 수, 처리 시간을 비교한다. 측정 전 속도 향상 배수나 운영 검증 완료를 선언하지 않는다.

구현과 위 검증 후 대표 확인용 합성 화면·캡처를 제공한다. 운영 화면에서 확인하려면 별도 배포 승인을 받아 기존 전용 관제 배포 절차로 진행하고, 실제 운영 확인을 별도로 보고한다.
