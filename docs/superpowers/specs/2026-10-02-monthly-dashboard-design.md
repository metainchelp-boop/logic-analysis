# 네이버 월간 대시보드·상태 카드 일관 필터

## 승인과 범위

대표가 월초~어제 기본 기간을 선택했고, 2026-10-02 조사 보고 후 “대시보드에 아직 남은 작업 이어서 해”로 제시한 구현의 진행을 승인했다. 기존 설계를 재사용한다. 개발·시험만 수행하며 운영 배포, 호출 제한 완화, 자동입찰, 업무 변경, 알림·공유 성과 활성화는 포함하지 않는다.

## 선택한 구조

즉시 화면 조회마다 네이버 호출하는 방식은 호출량·지연이 커지므로 채택하지 않는다. 별도 무제한 월간 작업도 채택하지 않는다. 기존 원천 수집의 같은 회차 예산 안에서 전일 수집을 우선하고 남는 예산으로 월간 집계를 수집·저장한다. 월간 기아 가능성은 숨기지 않고 확인/대기 수를 표시한다.

- 24호출/30초, 계정별8호출/10초, 초당3회, 회차 후60초 대기, 429 대기/중지, 단일 쓰기 소유자 보존.
- 전일과 월간은 같은 reader와 바깥 예산을 사용하며 같은 회차에 전일 시도한 계정은 월간에서 제외한다.
- 월간 키는 고객번호·기간 시작·기간 끝. 매일 월초~어제의 기간 합계를 덮어 갱신하며 날짜별 누적값들을 다시 더하지 않는다.
- schema9 추가 테이블은 기존 전일 기록과 분리. 이어읽기·0 증명·목록 변경·권한 재확인·재시도 상한 유지.
- 필요한 기본 지표 impCnt/clkCnt/salesAmt와 전환매출 convAmt. 전환매출 미수신은 기본 성과를 막지 않되 ROAS를 미확인으로 둔다. 추적 설정을 확인하지 못한 0 매출을 확인된 ROAS 0%로 선언하지 않는다.

## API 및 계산

인증 필수 GET `/api/naver-auto/dashboard?selection=...`. 화면 읽기는 저장소만 사용하며 네이버·ERP 호출 없음. 기존 이관 원장의 동일한 매칭/현재 계정/관리직원 본인 담당 경계를 재사용한다. 계정 수와 전산 광고주 수를 구분한다.

- 기간: KST 당월1일~어제. 매월1일은 기간0일·아직 집계 기간 없음, 전월 자료를 잘못 보여 주지 않는다.
- 전체 합계가 미완성이면 확인된 계정 부분합과 확인/전체 수를 함께 표시한다. 원천 불명/실패/낡음은 0이 아니다.
- 광고주 평균은 매칭된 전산 업체별 계정을 묶고 해당 업체의 모든 계정 월간 수집이 완결된 업체만 분모에 넣는다. 미매칭 계정은 광고주 평균에서 제외하고 수를 표시한다.
- 일평균 소진=확인된 기간 광고비/기간 일수. 광고주 일평균은 완결 업체의 기간 광고비/업체 수/기간 일수.
- CTR=동일 완결 모집단 클릭/노출×100, CPC=광고비/클릭. 0 분모는 미확인.
- ROAS=전환매출 확인 계정들의 동일기간 매출합/광고비합×100. 해당 계정 수·광고비·매출을 응답에 포함하며 전체 광고주의 단순 평균으로 표시하지 않는다.
- 어제 집행 확인=전일 완결자료의 노출/클릭/광고비 중 양수 존재, 어제 실적 없음=세 지표 모두0, 미확인=불완전 자료. 설정상 운영 가능/정지는 별도다.

## 화면

기존 `/naver/` 관제 주소를 보존하고 앞에 `/naver/dashboard` 탭 추가. 기존 밝은색 화면·원화 정수 표시·글자/여백/카드 체계를 유지한다. 수집 범위·기간·완결도 안내를 지표보다 앞에 둔다. 권한/담당자 변경·실패·늦은 응답 때 이전 수치를 남기지 않는다.

관제는 전체보기/확인 필요/긴급/주의/정상/점검 불가 6카드. 서버의 판정과 수를 사용한다. 목록·이슈·상향·완료 이슈에 현재 선택/검색의 동일 광고주 집합을 적용한다. 서버의 상향 권한 규칙은 변경하지 않고 표시되는 집합만 교차한다.

## 검증 및 남는 운영 단계

기간·월경계·누락·0·재시도·부분 이어읽기·합산/중복·담당 권한·GET전용·호출총량 시험, 실제 WSGI/중계 경로와 화면 PC/모바일/키보드/경합 시험을 수행한다. 실제 네이버/ERP 송신 및 운영 DB 편집 없이 가상 원천으로 검증한다. macOS SQLite 잠금 시험 제약은 완화하지 않고 기존 Ubuntu 격리 CI에서 검증한다. 배포 후 월간 최초 실자료 채움과 직원 실제 접속은 개발 시험 통과와 구분해 보고한다.
