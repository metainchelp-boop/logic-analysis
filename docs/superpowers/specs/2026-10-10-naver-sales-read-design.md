# 네이버 광고 영업 조회 권한

대표 승인 범위: 직원별 별도 권한을 만들고 본인이 계약한 정확히 진행중 업체의 진행 상태·성과를 읽는다. 이 작업 뒤 AI 자동화 세팅 개발을 이어간다. 실제 직원 권한을 일괄 부여하지 않는다.

## 판정

- ERP 대표만 재직 SALES 직원의 `naverSalesViewAccess`를 부여·회수한다. 기본 false.
- 기존 대표 ALL / MANAGEMENT MINE 권한은 그대로 둔다.
- 현재 유효기간의 계약에 기록된 실제 seller만 사용한다. `second_emp_idx`는 현재 영업 배정이며 대체 근거로 사용하지 않는다. 날짜/판매자 미상은 제외한다.
- 수락된 org의 `sales_contracts`와 catalog의 `stage_known=true, stage_hidden=false, stage=진행중`을 교차한다.
- 업체는 미연결이어도 연결 대기로 보인다. 성과·보고서는 현재 계정 연결과 교차하며 복수 계정은 별개로 표시한다.

## 서버

전용 `SALES_READ`를 신설한다. 관리 권한 함수에서는 이 scope를 닫는다. dispatcher는 GET `/me`, `/sales/clients`, `/sales/detail`, `/sales/report`와 기술 세션 갱신만 허용한다. 전체 기존 관리·쓰기 API는 차단한다. 영업 GET은 하나의 DB read snapshot에서 현재 권한·단계·연결을 다시 확인한다.

org 수락본이 당일/2시간 이내이고 최신 동기화 성공·미해결 hold 없음일 때만 조회한다. catalog 기존 2시간 수락 정책과 inventory 원천 확인도 유지한다. ERP 실시간 조회가 아니며 org 통상 1시간 갱신 지연이 있다. 즉시 철회라는 주장은 하지 않는다.

수치 응답은 계정별 최신 기간 저장판의 숫자 허용목록만 사용한다. 구형 합산을 개별 값으로 가장하지 않는다. 비교 수치는 이전 계정 범위를 별도 입증하기 전 초기 응답에서 제외한다. 보고서는 최신 수치판/계정/지문에 묶인 승인 공유 문안만 포함하고 내부 메모·광고주 요청·이력·초안·작성자 정보는 제외한다.

## 화면

영업 전용 `내 광고주 성과` 화면을 분리한다. 업체 검색·100개 페이징·주간/월간·계정별 성과·승인 보고서 보기/인쇄를 제공한다. 관리·변경·승인·연결 버튼은 없다. 조회 권한·원천 오류가 나면 이전 내용을 제거하고 늦게 도착한 응답도 버린다. 인쇄 직전 같은 서버 경계를 다시 확인한다.

## 구현·검증 순서

1. ERP BE additive permission/actual contract source + 대표/재직 SALES 경계 시험.
2. 엔진 저장 허용목록·조직 parser·SALES_READ·전용 projection/dispatcher.
3. 전용 UI와 ERP 두 직원 권한 저장 경로·메뉴·로그인 필드.
4. 다른 seller/임의 ID/검색/count/기존 API/쓰기/철회/퇴사/기간/미연결/구형 원천/공유 승인판/내부 메모 차단 시험 + 회귀 검사.
5. BE → 엔진 → FE 순서로 릴리스 준비·CI 확인. 운영 데이터 보존, 자동 권한 부여0. 실제 운영·직원 역할 검증 여부를 결과 HTML에 구분한다.
