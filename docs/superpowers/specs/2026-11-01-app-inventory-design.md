# 철거 전 앱 구성 조회 — 0단계

대표의 이번 작업 Codex 인수 지시로, 앞서 제시한 0단계(읽기 전용 기능 추가·검증·1회 조회)를 진행한다. 앱 종료·삭제·데이터 보관 실행·정산 변경은 이 기능의 범위가 아니다.

## 선택한 구조

기존 대표 계정/main 전용 naver-deploy 수동 workflow에 app-inventory 모드를 추가한다. 제품 소스·이미지 build·서비스 변경을 하지 않는다. 별도 workflow나 SSH 인증 경로를 만들지 않고 기존 전송·직렬화·해시 검증을 재사용한다. 기존 deploy/inspect/disk-usage/cleanup의 동작은 유지한다.

전용 Python 표준 라이브러리 수집기가 명령 원문을 메모리에서만 읽어 고정 허용 필드의 한 줄 JSON NAVER_DEPLOY_APP_INVENTORY를 출력한다. nginx 원문은 별도 순수 parser로 처리하고, 서버/위치/include 관계와 승인된 호스트·loopback/UNIX 연결만 요약한다. 알 수 없는 경로·값은 익명화/미확인으로 남긴다. 수집 실패·잘림·해석 불능을 정상/없음/0B로 바꾸지 않는다.

## 필요한 정보

- 대상 광고센터/콘텐츠/자동입찰 및 보호할 관제/로직분석 컨테이너의 실행·재시작·이미지·Compose 출처·mount·볼륨 정보.
- 현재 파일시스템 가용 바이트, 알려진 앱 디렉터리 사용 블록, DB/sidecar/암호화 키의 존재·크기/권한 등 메타데이터. DB·비밀 파일 내용을 읽거나 해시하지 않는다.
- nginx server/include/location·인증서 경로의 허용 메타데이터. 원문 헤더·비밀값·고객 경로는 출력하지 않는다. 복잡하거나 불완전한 해석을 실제 경로 확정으로 주장하지 않는다.
- 관련 systemd/timer 이름·상태, cron은 일치 앱별 개수/스케줄 존재만. 원문 ExecStart/Environment/cron command·로그·고객 행은 출력하지 않는다.

모든 외부 명령은 고정 배열(argv), 시간/출력 상한, stderr 비공개, shell=False로 실행한다. GET 앱/API 요청도 하지 않으며 시작·정지·삭제·DB 연결·새 백업·환경값 출력은 금지한다. Mac agent와 ERP 실제 데이터는 조회 범위 밖이며 미확인으로 남긴다.

## 검증과 완료

합성 Docker/nginx/파일/실패 입력에 비밀 canary를 넣어 허용 출력만 나오는지 검증한다. include/중첩/미확인 directive·시간초과·명령 실패/잘림·symlink 경계를 검사한다. 기존 배포 스크립트와 workflow 회귀 검사를 수행한다. 독립 소스/요구 검토 뒤 정확한 커밋 CI·비밀정보 검사·PR 병합·원격 SHA 확인을 거쳐, 새 모드만 1회 실행한다. 결과는 현재 스냅샷과 남은 불확실성을 나눠 로컬 보고서로 정리한다. 원본 출력 artifact는 만들지 않는다.
