# 네이버 관제 — 계정별 주간·월간 보고서 및 PDF 개편

작성일: 2026-10-04
상태: 시각 시안 확인 후 대표가 “이대로 진행해”로 구현 승인(2026-10-04). 운영 배포·외부 발송은 별도 승인 대상이다. 구현·검증 결과는 별도 작업 기록으로 남긴다.

## 1. 목적과 확정된 결정

- 여러 업체의 집계 상태 카드를 나열하던 보고서 탭을, 관리 담당자가 업체를 찾고 한 계정의 주간·월간 성과 보고서를 열어 내려받는 화면으로 바꾼다.
- 대표 답변: **계정별 보고서가 기본, 업체 전체 합산도 선택 가능**.
- 기본 대상은 현재 실관리 4단계(진행중·사후관리·전략관리·재계약진행중)이다. 과거 보고서와 비관리 계정의 수집 자료를 삭제하지 않는다.
- 대표는 전체 허용 범위, 관리 직원과 팀장은 본인 담당 범위를 유지한다. 목록·검색·상세·PDF용 데이터 모두 같은 권한을 적용한다.
- 주간은 월~일, 다음 월요일 10시 생성 대상. 월간은 월초~말일, 다음 달 3일 10시 생성 대상이라는 현재 규칙을 유지한다. 예약 시각을 수집 완료 보장으로 표현하지 않는다.
- 배포, 외부 발송, 공개 링크, AI 유료 호출, 광고 설정 변경은 이번 구현 승인에 포함하지 않는다.

## 2. 확인한 현행 구조

- `naver_engine/web.py`의 보고서 목록은 실관리 업체의 최신 업체×기간 스냅샷을 생성 시각 역순으로 20개씩 반환한다. 업체 검색·계정별 선택·주간/월간 필터는 없다.
- `naver_engine/reporting.py`의 저장 결과에는 업체 합계·비율·완결률·누락과 비교용 지문이 있다. 계정별 수치·일별 차트 값·전기간 비교는 저장하지 않는다.
- `naver_engine/store.py`에는 계정×실적일별 숫자·완결 여부·당시 업체 귀속·원천 개정 이력이 있다. 이 자료를 사용하며 화면/PDF를 열 때 네이버에 재수집 요청하지 않는다.
- 관제 엔진은 표준 라이브러리 기반이며 JSON 중계 경계를 사용한다. 현재 관제 PDF 다운로드 기능은 없다. 별도 광고센터의 AI 보고서 기능을 무단 호출하거나 변경하지 않는다.
- 옛 시안의 보고서 구성은 참고하되 예시 숫자·옛 발행 일정·자동 발송·옛 권한을 복원하지 않는다.

## 3. 화면과 사용 순서

1. 보고서 탭 첫 화면: `업체명 / 광고 계정 이름 / 광고 계정 ID 검색` + `주간 / 월간` 버튼 + 해당 주/월 선택.
2. 기본은 주간의 최근 생성 대상 기간. 주간/월간을 바꾸면 해당 종류의 최근 기간으로 이동한다. 같은 종류 안에서는 마지막 선택을 유지한다.
3. 실관리 업체의 연결된 광고 계정을 한 줄씩 표시한다. 업체명·계정명·광고 계정 ID·담당자·업무 단계·선택 기간·보고서 상태·최근 갱신 시각·보기 버튼을 제공한다.
4. 상태는 `생성 완료 / 부분 집계 / 수집 중 / 아직 생성되지 않음`을 구분한다. 보고서가 없다고 관리 계정 자체를 숨기지 않는다. 미연결 실관리 업체는 별도 개수/이관 현황 안내로 남기고 가짜 계정 보고서를 만들지 않는다.
5. 계정을 선택하면 한 장의 보고서 상세로 이동한다. 상단에서 `이 광고 계정 / 업체 전체 합산`을 선택한다. 합산에는 포함 계정과 개수가 보인다.
6. 상세 상단에 업체·계정·담당자·기간·판번호·데이터 기준시각과 `PDF 내려받기`를 둔다. 뒤로 돌아오면 검색·종류·기간·페이지를 복원한다.
7. 긴 수집 진단과 정정 이력은 접힌 보조 영역으로 옮긴다. 단, 부분 집계와 비교 불가 표시는 숫자 옆과 보고서 상단에 남긴다.
8. 기존 관제 업체 상세의 보고서 안내도 선택한 업체의 보고서로 연결한다. 다른 담당자의 업체 접근은 허용하지 않는다.
9. 기존 밝은 테마와 전체 폭 반응형을 유지한다. 작은 화면에서는 행을 카드로 바꾸어 페이지 전체 가로 스크롤을 만들지 않는다.

## 4. 보고서 내용과 숫자 규칙

- 핵심 성과: 광고비, 노출, 클릭, 클릭률, 클릭당 비용, 전환, 전환매출, 광고비 대비 전환매출(ROAS).
- 직전 동일 단위 기간 비교: 전주/전월의 숫자와 증감. 같은 기간의 정정 전후 차이와 구분한다.
- 일별 추이: 광고비·노출·클릭. 누락 날짜를 0으로 채우거나 연결선으로 정상 수치처럼 보이지 않게 한다.
- 간단 성과 요약: 검증된 숫자와 증감만으로 작성하는 정형 문장. 원인·고객 의향·미래 매출을 추정하지 않는다. AI 브리핑/담당자 코멘트 편집은 후속 기능이며 이번에는 자동 호출·새 업무 저장 기능을 켜지 않는다.
- 기간 이슈: 기간과 해당 계정의 귀속이 확인되는 저장 이력만 사용한다. 현재 열린 이슈를 과거 기간 이슈로 소급하지 않는다. 근거가 없으면 기록 미확인을 표시한다.
- 기본 성과와 전환 성과의 수집 상태를 분리한다. 전환 미수집을 매출 0이나 ROAS 0%로 표현하지 않는다.
- 전기간 자료 부족·계정 범위 변경·분모 0이면 증가율을 억지로 계산하지 않는다. 각각 `비교 자료 부족 / 비교 범위 변경 / 산출 불가`를 표시한다.
- 금액은 원 단위로 표시하되 계산 원본의 정밀도는 보존한다. 비율은 합산 후 계산하고 계정별 비율의 단순 평균을 쓰지 않는다.

## 5. 저장·조회 변경 범위

- 기존 업체×기간 보고서 및 옛 판은 그대로 보존한다. 새 형식의 보고서 판에 계정별 합계·일별 값·업체 합산·비교 대상 판과 원천 개정 정보를 함께 고정한다.
- 숫자가 같아도 출력 형식이 바뀐 판은 식별할 수 있도록 형식 버전을 지문에 포함한다. 새 판 생성은 기존 단일 쓰기 경로에서 수행한다.
- 과거 판에 없는 상세를 현재 값으로 덧붙이지 않는다. 원천으로 재구성할 수 있으면 `상세 재구성` 표시를 가진 새 판으로 생성한다. 입증할 수 없는 값은 미보관으로 남긴다.
- 업체×계정×실적일의 당시 귀속 규칙을 재사용한다. 현재 업체 연결이 바뀌어도 이전 업체의 성과를 새 업체 보고서로 옮기지 않는다.
- 비교 대상도 원천과 판을 고정한다. 과거 원천 정정으로 이번/비교 기간 값이 바뀌면 후속 판을 생성하며 기존 다운로드 사본은 바꾸지 않는다.
- 검색·필터는 서버에서 현재 권한과 실관리 범위를 먼저 적용한 뒤 페이지를 나눈다. 현재 화면의 20개 행만 검색하거나 다른 담당자의 이름/건수를 노출하지 않는다.
- 상세 요청은 회사, 계정, 기간, 판의 조합을 검증한다. 이전 판과 최신 판을 섞어 보여 주지 않으며 범위 밖과 없는 자료의 오류는 동일하게 처리한다.
- 캐시/증분 반영 키에 업체·계정/합산 구분·종류·기간·판을 반영한다. 빠른 검색 변경이나 권한 변경 뒤 오래된 응답이 새 화면을 덮지 않게 한다.

## 6. PDF 방식과 전달 편의

비교한 방식:

1. **권장: 인증된 보고서 데이터로 브라우저 안에서 PDF 파일 생성.** 화면과 같은 판을 쓰며 외부 변환 서비스에 자료를 보내지 않는다. 기존 엔진/중계의 JSON 경계를 유지한다. 한글 폰트와 생성 라이브러리는 검증 후 앱 자산으로 고정한다.
2. 서버 생성: 중앙에서 출력을 통제하기 쉽지만 엔진 이미지 의존성·중계 바이너리 응답을 추가해야 한다. 이번에는 선택하지 않는다.
3. 브라우저 인쇄창만 제공: 변경은 작지만 사용자가 다시 PDF 저장을 선택해야 하므로 요청한 직접 다운로드의 대체로 쓰지 않는다.

출력 기준:

- A4 PDF를 직접 내려받는다. 제목·본문·표는 검색 가능한 텍스트로 출력하고, 한글 폰트·자동 줄바꿈·페이지 나눔·페이지 번호를 검증한다.
- 파일명: `업체명_광고계정ID_주간또는월간_시작일_종료일_v판번호.pdf`. 업체 합산은 계정 ID 대신 `전체합산`을 넣는다. 파일명 제어문자·경로문자를 제거한다.
- 내용: 업체/계정/기간, 핵심 성과, 전기간 비교, 일별 추이, 근거 있는 요약, 자료 기준시각·판번호·집계 범위.
- 내부 업무 메모, 로그인/API 정보, 직원용 오류 원문, 비즈머니 잔액, 내부 검토 의견은 넣지 않는다. 광고주에게 필요한 데이터 누락 고지는 포함한다.
- 부분 집계도 내려받을 수 있지만 상단에 `부분 집계`와 해당 항목을 명확히 표시한다. 수집 중 자료를 확정 보고서로 표시하지 않는다.
- 다운로드 직전 현재 권한과 선택 판을 다시 확인한다. 라이브러리·폰트 실패 때 성공으로 표시하거나 HTML을 PDF 확장자로 저장하지 않는다.
- 기본 발송 흐름은 담당자가 상세와 PDF를 확인한 뒤 기존 메일/메신저에 직접 첨부하는 것이다. 자동 발송이나 공유 권한을 활성화하지 않는다.

후속 추천(이번 구현 제외): 광고주용 담당자 브리핑, 짧은 전달 문구 복사, 실제 발송을 별도로 확인하는 발송 기록, 만료/회수 가능한 공유 링크. PDF 다운로드만으로 발송 완료 처리하지 않는다.

## 7. 검증 및 진행 순서

1. 집계 시험: 계정 2개 분리/합산, 주간/월간 경계, 누락과 실제 0, 분모 0, 계정 이동, 원천 정정, 같은 합계의 날짜별 변화, 과거 판 보존.
2. 조회 시험: 전체 데이터 대상 검색·종류/기간 필터·페이지 이동, 보고서 없는 관리 계정, 퇴사/담당 변경/다른 업체 직접 요청 거절, 캐시와 지연 응답.
3. 화면 구현 및 시험: 검색→계정 선택→종류·기간 변경→합산 전환→목록 복귀, 320px/일반 PC/넓은 화면에서 가로 넘침 없음.
4. PDF 시험: 화면과 동일한 판/숫자/범위, 여러 계정 합산, 부분 집계, 긴 한글 업체명, 여러 페이지, 폰트 실패, 권한 만료, 직접 파일 다운로드 및 파일 열기.
5. 기존 보고서/관제/이관/권한 관련 회귀 시험. 로컬 합성 자료 시험과 운영 검증은 별도로 보고한다.
6. 검증 결과와 남은 한계를 정리한다. 운영 배포는 별도 승인 후 수행하며 실서비스를 수정하지 않은 상태를 배포 완료라고 말하지 않는다.

예상 작업량: 구현·검증 약 3~5시간의 추정. 최종 설계 확인, 배포 승인 대기, 새로 발견된 원천 자료 문제의 해결 시간은 별도다.
