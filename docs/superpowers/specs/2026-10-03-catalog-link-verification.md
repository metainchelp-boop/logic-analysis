# 업체 목록·연결 확인 통일 검증

## 변경 범위

제품 변경 `c0131c549efcb7397153471ade7fd91e30a53987`, 시험 계약 보완 `6e4b035901027fef29266de218bfb0594227a3fe`, 기존 PR #12의 개발 브랜치. 배포·운영 연결·전산 번호 변경은 하지 않았다.

종전 결함은 `2026-10-03-managed-matching-gaps.md` 참조. 검증 모드에서 이관 현황에는 있지만 기존 prospects에는 없는 업체도 같은 수락 catalog 기준으로 연결 확인에 나타나게 했다. 기존 prospects·저장 pairing·아침 점검·보고서 자격을 확장하지 않았다.

- 대표/본인 담당 및 상단 담당 선택 범위에서만 노출·확정한다.
- 원천 내용·담당 범위·토큰 축소 상태·연결쌍·판단 이력에 ref를 결합한다. 같은 catalog 시각의 내용 교체도 옛 ref를 무효화한다.
- 이름만 비슷한 후보·번호 충돌은 확정하지 않는다. 이름 불일치는 원본 광고 계정 ID 단건 대조를 요구한다.
- 저장 큐와 실제 SQL 거래 안에서 재검사한다. catalog 최초 실패·만료가 기존 목록으로 우회하지 않는다.
- 해당 업체 바로가기·전체보기·빈 결과 안내를 제공한다. 상세가 없는 업체에 잘못된 기존 상세 링크를 만들지 않는다.
- 일괄 확인은 50개마다 최신 ref를 다시 읽되 최초 선택한 연결쌍만 이어간다. 새 업체·변경된 후보를 포함하지 않는다.

## 로컬 검증

- 공개 WSGI→실제 Store·메모리 SQLite 회귀 20개 통과. 외부 socket 연결을 거절한 상태다.
- 기존 화면 정적 규칙 9개, 미승인 API 경로 차단 1개 통과. 위와 합쳐 Python 30개다.
- 실제 app.js DOM/API 계약 검사 33개 통과. 실제 브라우저 검증과 구별한다.
- 별도 합성 공개 WSGI에서 이름·번호가 같은 2개 계정의 묶음 확정 통과.
- 합성 1,793계정/764업체에서 목록 생성 0.198초, 마지막 50개 ref 탐색 0.081초. 메모리 SQL 단일 측정이며 운영 서버·디스크·HTTP 수집 속도 추정이 아니다.
- 독립 검토에서 일반 모드에 selection 본문을 보내 기존 refs 전용 API가 400을 반환하는 회귀를 발견했다. verified 모드에서만 보내도록 수정하고 DOM/API 회귀를 추가했다.

macOS 파일 기반 Store 시험은 기존 초기화 오류로 완료하지 못했다. 파일 잠금·실제 Chromium→중계→WSGI→Store 검사는 외부망·실제 자격을 차단한 Linux CI에서 별도로 검증한다.

## 남은 운영 절차

개발 시험 성공은 배포·실제 광고주 연결 완료를 뜻하지 않는다. 운영 반영 후 이름 불일치 대상의 현재 저장 번호·원본 번호·업체 연결쌍을 대조하고, 충돌은 별도 대표 확인 대상으로 유지한다. 운영 11곳이 모두 이 코드 원인이라고 단정하거나 이미 연결됐다고 보고하지 않는다.
