# 이관 현황 두 분류 전환·관제 상향 목록 접기 설계

## 상태와 요청

- 대표 요청: `전산 실관리 업체 · 계정 누락 대조`와 `이관 광고 계정 전체`를 한 화면에 동시에 펼치지 않고 버튼으로 원하는 분류만 보도록 개선한다.
- 추가 요청: 관제의 `나에게 올라온` 목록이 늘 펼쳐져 `오늘의 이슈`가 밀리므로 접기·펼치기를 추가한다. 코드의 `renderUp()`은 현재 필터를 통과한 `escalated_to_me` 전부를 `upbox`에 펼치며 접힘 상태가 없다.
- 기준 소스 `0a56879`, 구현 직전 `d446693`. 대표가 2026-10-03 “응 진행해”로 두 구성을 승인했다. 현재 두 영역은 `s-transfers` 안에서 같은 `/accounts` 응답을 공유한다. 구현·시험 범위이며 운영 배포는 별도다.
- 두 변경을 함께 구현·검증하는 예상 시간은 25~35분이다. 운영 배포·네이버 재수집·전산 원본 수정은 제외한다.

## 대안과 권고

1. **권고: 이관 현황 안의 두 전환 버튼.** 공통 요약 카드를 유지하고 선택한 목록만 전체 폭으로 표시한다. 기존 주소·권한·자료 흐름을 유지한다.
2. 별도 페이지 두 개로 분리하면 직접 주소 공유는 쉬워지지만 상단 메뉴와 경로가 늘어난다. 현재 요구에는 불필요하므로 채택하지 않는다.

## 대표 확인할 구성

- 공통 상단: 기존 요약 카드, 수집 상태·확인 시각, `목록 새로고침`.
- 그 아래 버튼: `전산 실관리·누락 대조` / `이관 광고 계정 전체`. 선택된 버튼을 명확히 표시하고 연결된 영역 하나만 노출한다.
- 최초 진입 기본은 `전산 실관리·누락 대조`로 제안한다. 같은 로그인 창에서는 마지막 선택을 유지한다. 로그인 종료/교체 때 초기화하며 업체 자료를 영구 저장하지 않는다.
- 첫 분류는 현재 담당 범위의 실관리 업체·계정 누락 대조만 보인다. 둘째 분류는 현재 계정 목록과 검색·매칭·업무 단계 필터를 보인다. 둘을 오가도 계정 필터/검색어는 보존한다.
- 공통 요약 카드를 누르면 `이관 광고 계정 전체`로 전환하고 해당 카드의 기존 필터·검색 초기화 동작을 적용한다.
- `아래 계정 목록`처럼 동시에 표시됨을 전제한 안내는 버튼 이름을 가리키도록 고친다. 기존 짝 확인·관제 포함/제외·수동 조회 기능과 권한은 그대로 둔다.
- 버튼 전환 때도 기존 저장 자료 조회로 현재 권한을 재확인한다. 확인 전 새로 열 영역은 가리고, 성공 후 기존 DOM/변경분을 표시한다. 실패 시 권한 오류와 일시 통신 오류 처리 규칙을 유지한다. 새 API·수집 요청·별도 캐시는 만들지 않는다.
- 좁은 화면에서는 전환 버튼과 필터를 줄바꿈하고 기존 표의 반응형 행 표시를 유지한다. 전체 페이지 가로 넘침 여부를 실제 브라우저로 확인한다.

## 구현·검증 범위

- `backend/naver_page/index.html`: 전환 버튼, 공통 새로고침 위치, 영역 연결·안내.
- `backend/naver_page/app.js`: 선택 영역, 전환·권한 재확인, 요약 카드 연계. 기존 `/accounts`와 변경분 처리 보존.
- `backend/naver_page/app.css`: 선택 표시·숨김·줄바꿈. 아래 승인 대상 관제 접기 외 다른 탭 디자인은 변경하지 않는다.
- 검증: 초기 노출 하나, 버튼/키보드 전환, 왕복 검색 유지, 카드 누르면 계정 분류 열기, 늦은 응답·권한 오류 노출 차단, 기존 변경분 갱신, 1440/1024/390폭 가로 넘침 검사. 합성 자료만 사용한다.

## 추가 구성: 관제의 나에게 올라온 목록

- 권고는 같은 위치에서 기본 접힘이며 제목·현재 필터 기준 건수·`펼치기` 버튼만 남긴다. 상세 목록만 접어 `오늘의 이슈`가 바로 이어지게 한다. 별도 팝업으로 옮기는 대안은 확인 단계가 늘어나므로 사용하지 않는다.
- 펼치면 현재 업체별 사유·대기 시간·상세 이동을 그대로 표시하고 `접기` 버튼을 제공한다. 접힘 상태에서도 미처리 건수는 계속 보인다.
- 같은 로그인 창의 목록 새로고침·필터 변경·다른 탭 왕복에는 사용자가 선택한 접힘 상태를 유지한다. 브라우저 페이지 재로딩(F5)은 새 화면 인스턴스로 기본값을 사용하며 별도 영구 저장은 하지 않는다. 새 항목 때문에 강제로 펼치지 않고 건수만 최신화한다. 로그아웃·로그인 교체·담당 범위 변경 시에는 기본 접힘으로 돌아간다.
- 권한은 현재 `watchItems`/`view-unverified`/오류 시 DOM 제거 경계를 유지한다. 접기·펼치기 자체로 읽음·확인 중·해결 처리하거나 업무 API를 호출하지 않는다. 필터 결과 0건이면 기존처럼 영역 자체를 숨긴다.
- 실제 버튼과 `aria-expanded`/`aria-controls`를 사용한다. 키보드 조작과 갱신 중 버튼 초점 유지, 접힌 목록이 키보드 탐색 대상에서 제외되는지 확인한다.
- 검증: 다수 항목 최초 접힘, 펼침/접힘과 링크 이동, 변경분 갱신 후 상태·개수 일치, 새 항목 강제 펼침 없음, 필터 0↔여러 건, 권한 전환·종료 시 이전 자료 제거, 제품 쓰기 0회, 이슈 제목이 불필요한 목록 아래로 밀리지 않는 배치.
