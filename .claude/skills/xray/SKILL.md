# 경쟁 서비스 해부 (/xray)

`/xray 아이템스카우트` 처럼 부른다. 인자가 없으면 **대상 서비스명을 먼저 묻는다**(추측으로 고르지 않는다).

## 원칙 (항상)

- **공개 자료만** 쓴다 — 공식 사이트·요금 페이지·앱스토어/크롬 웹스토어 설명·공개 리뷰. 상대 서비스에 **로그인·가입·스크래핑·자동화 접속 금지**. 우리 수집기가 차단당한 역사가 있다 — 남의 서비스에도 같은 일을 하지 않는다.
- **우리 쪽은 코드로 잰다.** 「우리도 된다」는 말은 **파일 경로·엔드포인트**를 인용할 수 있을 때만 적는다. 추측·기억은 「미확인」으로 적는다.
- 근거가 없는 칸은 비워 두지 말고 **「미확인(출처 없음)」** 이라고 쓴다. 빈 칸은 「없다」로 읽힌다.
- 이 저장소는 공개다 — 산출물에 **토큰·API 키·업체명(우리 광고주)** 을 쓰지 않는다. 키워드는 괜찮다.
- 산출물은 저장소 규칙대로: **자체완결 HTML · 한글 파일명·제목 · 밝은 테마 고정 · 표준 파랑 `#3b82f6` · 외부 의존성 0** · `SendUserFile` 전달.

## 절차

### 1. 자료 수집 — 상대 서비스
순서대로 시도하고, 각 단계에서 **무엇이 막혔는지** 산출물 「출처」 칸에 남긴다.

1. `WebSearch` 로 공식 사이트·요금·리뷰·앱스토어·크롬 웹스토어 링크를 모은다(한국어 질의 2~3개: 「<이름> 기능 요금제」 「<이름> 순위 추적 방식」 「<이름> 리뷰 단점」).
2. `WebFetch` 로 공식 페이지 → 요금 페이지 → 앱스토어/웹스토어 설명 순으로 읽는다.
   ⚠️ **이 환경은 국내 사이트 상당수가 `EGRESS_BLOCKED` 로 막힌다**(2026-09-15 실측: itemscout.io · chosunseller.kr 차단). 막히면 **재시도하지 말고** 다음 출처로 간다 — 검색 결과 스니펫 · `apps.apple.com` · `chromewebstore.google.com` · 다른 리뷰 도메인.
3. 그래도 핵심(요금·추적 한도·수집 방식)이 비면 **대표께 화면 캡처 2~3장을 요청**하고, 그 전까지는 「미확인」으로 낸다. 질문은 한 번에 모아서.

### 2. 자료 수집 — 우리(로직분석)
코드에서 직접 센다. 최소 이만큼은 본다:
- 엔드포인트 목록: `grep -rhoE '@(router|app)\.(get|post|put|delete)\("(/[^"]*)' backend/*.py` + `prefix=` 8개(`/api/auth·chat·cd·clients·collector·internal/handovers·reports·seo`).
- 순위 수집 방식: `collector-extension/`(쇼핑 · 사람 클릭 방식 · IP·상한 규칙은 `backend/collect_cap.py`·`collector.py` `HOURLY_CAP`) · `extension-place/`(플레이스).
- 검색량 출처: `backend/datalab.py` · `/api/keyword/volume` · 네이버 공식 쇼핑검색 API 는 **2026-07-31 종료**(WORKLOG 2026-08-11) — 「API 로 순위를 받는다」고 적지 말 것.
- 순위 매칭 규칙: `backend/naver_crawler.py find_product_rank_from_cache`(nvMid 1순위 → URL 포함 → 스토어명).
- 광고 구분: `collector-extension/rank_rules.js`(`organic-v3`).
- 리포트·제안서: `backend/reports.py` · `weekly_report.py` · FE `metainc-web-frontend/public/proposal/`.
- 상권: `backend/sbiz365.py`.
- 최신 상태는 `CLAUDE.md` 「현재 진행 중 작업」 맨 위 3줄 — 지금 수집이 도는지 멈췄는지를 **그대로** 적는다(멈춰 있으면 비교표에도 멈춰 있다고 쓴다).

### 3. 비교 축 (고정 9축 — 순서 바꾸지 않는다)
| # | 축 | 상대 | 우리 | 근거(파일·URL) |
|---|---|---|---|---|
| ① | 순위 데이터를 **어떻게 얻나** (자체 IP·확장·크롤·API·사용자 브라우저) | | | |
| ② | 키워드 분석 — 검색량 출처·연관 키워드·경쟁도 | | | |
| ③ | 순위 추적 — 입력 단위(상품 ID/URL/상호)·깊이(몇 위까지)·주기·한도·알림 | | | |
| ④ | 상품·경쟁사 분석 (리뷰·가격·카테고리·상세페이지) | | | |
| ⑤ | 광고와 오가닉 구분 | | | |
| ⑥ | 보고서·제안서·공유 링크 | | | |
| ⑦ | 요금·대상 고객·좌석 수 | | | |
| ⑧ | 우리가 못 하는 것 / 우리만 하는 것 | | | |
| ⑨ | 다음 개발 후보 — **대표 결정 항목**으로 2~5개, 각 항목에 「왜」·「얼마나 큰 일」·「무엇에 의존」 | | | |

축 ③ 은 **입력 단위**를 반드시 갈라 적는다 — 「상품 ID(mid) 직접 입력」이 되는지가 매칭 정확도를 가른다(우리는 스마트스토어 주소 숫자 ≠ nvMid 라 3순위(스토어명)로 떨어지는 상품이 있다, WORKLOG 2026-09-15).

### 4. 산출물
- 파일명 예: `경쟁사-해부-아이템스카우트-vs-로직분석.html`. `<title>` 도 한글.
- 구성: **한 줄 결론**(우리가 어디서 이기고 어디서 지나) → 9축 표 → 「미확인」 목록과 그 이유(막힌 출처) → 대표 결정 항목(⑨) → 출처 링크 목록.
- 상단에 `업데이트 YYYY-MM-DD · v1` 스탬프. 같은 서비스를 다시 해부하면 **같은 파일명에 v2** 로 갱신하고 변경 이력을 아래에 남긴다.
- `SendUserFile` 로 보낸 뒤, 채팅에는 결론 3~5줄과 「미확인」 개수만 적는다(표를 채팅에 다시 붙이지 않는다).

### 5. 하지 않는 것
- 상대 서비스의 유료 화면·로그인 뒤 화면을 추측해서 채우지 않는다.
- 비교 결과로 **코드를 바로 바꾸지 않는다** — ⑨ 는 대표 결정 항목이고, 착수는 시안 확정 뒤다(저장소 규칙).
- 검색량·순위 같은 수치를 상대 서비스에서 **직접 조회해 오지 않는다**(요청 1건도 안 보낸다).
